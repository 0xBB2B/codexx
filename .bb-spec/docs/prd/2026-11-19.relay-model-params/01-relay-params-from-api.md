# 中转模型参数取自接口

## 用户故事

### P0：作为用户，我想让 Codex 里的中转模型参数和中转实际提供的一致，以便不会因为参数不对而请求失败或浪费上下文

**用例（主路径）**
- 场景：小林已经开了转发，配置名叫「A家」。A家的模型列表接口返回下面 3 个模型：
  - `model-a`：上下文 `context_length` 是 1048576，思考等级 `reasoning.supported_efforts` 是 `["low","high","max"]`，输入类型 `architecture.input_modalities` 是 `["text"]`。
  - `gpt-x`：和官方模型同名。官方条目的上下文是 272000，接口给的是 1050000，思考等级是 `["none","low","medium","high","xhigh","max"]`。
  - `auto`：接口没给任何参数。
- 操作：重启 ChatGPT，打开模型选择器，逐个看这 3 个模型。
- 预期：
  - 「A家 · model-a」：上下文 1048576；思考等级可选 low、high、ultra，默认 high；不能附图片。
  - 「A家 · gpt-x」：上下文 1050000；思考等级可选 none、low、medium、high、xhigh、ultra，默认 high。
  - 「A家 · auto」：上下文 1000000；能附图片；没有思考等级可选。

### P0：作为用户，我想让中转新上的模型直接出现在 Codex 里，以便不用等本工具发新版

**用例（主路径）**
- 场景：A家新上了 `model-new`，接口带了它的全部参数。本工具从来没见过这个模型名。
- 操作：在主窗口点「重试」刷新模型列表，然后在 Codex 里打开模型选择器。
- 预期：出现「A家 · model-new」，参数等于接口返回值。主窗口的模型数加 1。

**用例（边界 / 异常）**
- 场景：A家接口还返回了 `review-x`，没有参数。官方清单里有同名的 `review-x`，在官方那边是隐藏的。预期：模型选择器里看不到「A家 · review-x」，主窗口模型数也不算它；Codex 内部用 `relay-review-x` 发请求时，请求会转到A家。
- 场景：A家接口返回的 `model-b` 只给了上下文，没给思考等级和输入类型；官方清单里没有 `model-b`。预期：「A家 · model-b」的上下文等于接口值，输入类型和官方第一个模型一样，没有思考等级可选。
- 场景：A家接口返回的 `model-c`，思考等级是 `["low","turbo","medium"]`。预期：只有 low、medium 两档可选，默认 medium。
- 场景：这次获取A家的模型列表超时；上次成功获取时缓存了 4 个模型和它们的参数。预期：Codex 里还是那 4 个模型，参数和上次一样。主窗口提示这次没有更新。
- 场景：本机只有升级前旧版本留下的缓存，里面只有模型名，没有参数；这次获取又失败了。预期：缓存里的模型照样显示，每个都按"接口没给参数"来补（规则见 C4）。

## 约束

- C1 中转模型的范围：中转模型列表接口返回的每个模型（模型名不为空）都进合并模型目录。本工具内部不存任何中转模型的名单或参数表。
- C2 参数来源（`auto` 除外，`auto` 按 C3）：
  - 上下文窗口 = 接口的 `context_length`。
  - 输入类型 = 接口的 `architecture.input_modalities`。
  - 思考等级 = 接口的 `reasoning.supported_efforts`，按接口里的顺序排。不认识的等级名去掉。认识的等级名只有 7 个：none、minimal、low、medium、high、xhigh、max。
  - 和官方模型同名的中转模型同样按这条取值，不用官方条目的值。
- C3 模型名为 `auto` 的中转模型，一律用固定参数，不管接口给不给：上下文窗口 1000000，输入类型是文字和图片，没有思考等级。
- C4 接口缺参数时怎么补（`auto` 除外）。下面三种情况都算"缺"：字段不存在；上下文不是正整数；输入类型列表为空。缺哪一项就只补哪一项：
  - 中转模型和官方模型同名：缺的那项用同名官方条目的值；缺思考等级时，默认思考等级也用官方条目的。
  - 不同名：缺上下文或输入类型，就用官方清单第一个模型的值；缺思考等级，就是没有思考等级可选。
- C5 默认思考等级（思考等级取自接口时）：等级里有 high 就默认 high；没有 high，就默认按 none < minimal < low < medium < high < xhigh < max 排序后最高的一档。没有思考等级可选的模型，不设默认等级，也不能切换等级。
- C6 思考等级取自接口时，等级 `max` 在目录里写成 `ultra`。用这类模型发请求时，推理强度如果是 `ultra`，先改回 `max` 再发给中转。思考等级取自官方条目的模型，等级名原样不变。
- C7 显示和隐藏：中转模型和官方清单里隐藏的模型同名时，在目录里也设为隐藏。隐藏模型能接收请求，但不出现在模型选择器里，也不计入主窗口的模型数。其余中转模型都显示。转发关着、本机又找不到 ChatGPT 时，无法知道官方隐藏了哪些模型，主窗口按"全部显示"来计数。
- C8 顺序：中转模型排在官方模型后面。多个配置时按配置顺序排；同一个配置里，按接口返回的顺序排。
- C9 缓存：获取模型列表成功时，把模型名和参数一起保存。获取失败时，模型名和参数都用上次成功保存的那份。缓存里只有模型名、没有参数时（升级前旧版本留下的缓存），每个模型按 C4 的"缺参数"来补。

## 验收

- [ ] C1：测试中转返回一个本工具代码和数据里都没出现过的模型名 → 它出现在合并模型目录里。在发布物里搜不到内置参数表文件。
- [ ] C2：`model-a` 的接口返回值是 1048576、`["low","high","max"]`、`["text"]` → 目录条目的上下文窗口是 1048576，可选等级依次是 low、high、ultra，输入类型只有 text。同名的 `gpt-x`，接口给 1050000、官方条目是 272000 → 目录条目是 1050000。
- [ ] C2：接口思考等级是 `["low","turbo","medium"]` → 目录条目的可选等级是 low、medium。
- [ ] C3：接口给 `auto` 的上下文是 500 → 目录条目仍是 1000000，输入类型是 text 和 image，没有可选等级。接口完全没给 `auto` 参数 → 结果相同。
- [ ] C4：同名模型缺全部参数 → 上下文、输入类型、可选等级、默认等级都等于同名官方条目的值。不同名模型只缺思考等级 → 上下文和输入类型等于接口值，没有可选等级。不同名模型的上下文是 0 → 上下文等于官方清单第一个模型的值。
- [ ] C5：`["low","high","max"]` → 默认 high。`["none","low","medium","xhigh"]` → 默认 xhigh。`["low","medium"]` → 默认 medium。空列表 → 不设默认等级，也不能切换等级。
- [ ] C6：用思考等级取自接口的模型发一个推理强度是 `ultra` 的请求 → 测试中转收到的是 `max`。用思考等级取自官方条目的同名模型发 `ultra` → 测试中转收到的是 `ultra`。
- [ ] C7：和官方隐藏模型同名的中转模型 → 目录里设为隐藏，不计入主窗口模型数，用它的内部名发请求能转到中转。转发关着、找不到 ChatGPT 时，主窗口模型数等于接口返回的模型数。
- [ ] C8：两个配置分别返回 `[m2, m1]` 和 `[m3]` → 目录里中转部分的顺序是配置1·m2、配置1·m1、配置2·m3。
- [ ] C9：先成功获取一次，再让中转连不上并刷新 → 目录里的中转模型和参数和成功那次完全相同。只放旧格式缓存（只有模型名）、获取又失败 → 模型都在，参数按 C4 补。

## 验证路径

1. 启动一个测试中转，让它的模型列表接口返回用例里的 `model-a`、`gpt-x`、`auto`、`review-x`、`model-b`、`model-c`，开启转发 → 合并模型目录里每个条目的参数符合 C2~C7；主窗口模型数是 5（隐藏的 `review-x` 不算）。
2. 在测试中转里加一个 `model-new`，点「重试」→ 目录里多出这个模型，主窗口模型数变成 6。
3. 关掉测试中转，点「重试」→ 目录和第 2 步完全相同，主窗口提示这次没有更新。
4. 用「配置名 · model-a」选 ultra 发一条消息 → 测试中转收到的推理强度是 `max`。
