# 提示条不再挡住按钮

## 背景与问题
主窗口、首次设置窗口和表单弹窗里的提示条，都是横贯窗口的长条，浮在内容最上面。主窗口里它正好盖住转发总览的转发开关、「只用中转」开关和「重新检测」：用户刚点完开关，弹出的提示就把开关挡住。成功提示要 4 秒才消失，警告和错误一直留着，要先点 ✕ 才能接着操作。首次设置窗口和弹窗里，长一点的提示会盖住输入框。用户 2026-11-26 原话："现在有点遮挡按钮了，侵入性太强了"。

## 目标
- 主窗口、首次设置窗口里的提示条不盖住任何按钮、输入框、开关，窗口高度仍不因提示改变。
- 表单弹窗里的错误提示不盖住任何东西。
- 三处的提示条都从左上角开始，macOS 和 Windows 一致。

## 非目标
- 不改提示条本身的样子（颜色、图标、内边距、圆角、✕ 按钮）和文案。
- 不改提示的去留规则：成功和信息 4 秒自动消失，警告和错误留到点 ✕ 或问题解决，同标题同级别原位替换。
- 不改确认类弹窗（删除配置、卸载等）。

## 整体验证路径
1. 主窗口转发开着，ChatGPT 运行中，点「只用中转」开关 → 左上角弹出成功提示，转发开关、「只用中转」开关、「重新检测」都没被盖住，还能点。
2. 首次设置窗口填一个连不上的 Base URL 点「完成设置」→ 左上角弹出错误提示，三个输入框和「完成设置」都没被盖住，窗口高度不变。
3. 主窗口点「编辑」，把 API Key 改成无效值点「保存」→ 错误提示出现在标题下面、「名字」上面，弹窗变高；点 ✕ 后弹窗变回原来的高度。

## 决策记录
- **质疑结论：值得做**（2026-11-26）。最常用的操作就是点开关，点完提示正好盖住开关，每次都碰到；缩短文案或提前消失解决不了警告和错误一直挡着的问题。
- **范围：主窗口、首次设置窗口和表单弹窗都改，四种提示都换位置**（用户 2026-11-26 选定）。被否决：只改主窗口（其他窗口的提示同样会盖输入框）；只换会自动消失的两种（警告和错误挡得最久）。
- **主窗口：左上角、宽 376px，仍浮着、窗口高度不变**（用户 2026-11-26 看原型选定，方案 B）。原因：挡按钮的根因是通栏浮条盖在控件上，主窗口里唯一够高、又没有控件的地方是转发总览左边的图标、标题和说明，收窄到 376px 后量过的所有情况都不盖控件（离最近的开关 63px，最长的错误条离「添加配置」100px）。被否决：放到底部靠左（底部空地只有 96px，带按钮的错误条会盖住「添加配置」，还盖住状态栏）；插进内容把下面往下推（主窗口变高 97～230px，推翻 2026-11-13 定的"不挤开内容"和多中转 PRD 的"窗口高度不变"）。
- **三处都从左上角开始**（用户 2026-11-26 看展示页后提出："不是应该都在左上角吗？"）。首次设置窗口原本想放底部，改成和主窗口同一个位置。"浮在窗口上方"不要求一定在顶部（用户 2026-11-26 答复），但这次统一放左上。
- **首次设置窗口宽 608px**（用户 2026-11-26 选定）。量下来 376～544px 时最长的错误文案会盖住「名字」输入框上沿 5px，608px 时离输入框还有 14px。被否决：376px 和主窗口一样宽（少见情况下盖输入框）；插进内容（窗口变高约 100px）。真机字宽可能多折一行，实现后要用真机对比确认。
- **表单弹窗：错误提示插进正文最上面，弹窗跟着变高**（用户 2026-11-26 选定）。原因：标题和「名字」输入框之间只有 48px，最矮的提示条就有 54px，浮着一定盖住输入框。这条替换 DESIGN.md 原来"弹窗里的错误提示不改变弹窗高度"的规定。
