# 多中转配置

## 用户故事

### P0：作为同时有几家模型服务的用户，我想把它们都接进 Codex，并在模型列表里分清哪个模型来自哪家

**用例（主路径）**
- 场景：小周已有升级来的配置「中转」，又买了一家服务。
- 操作：主窗口点「添加配置」，填名字「A家」、Base URL `https://relay2.example.com/v1`、API Key `sk-example-0000`，点「保存」；自己重启 ChatGPT。
- 预期：弹窗关闭，窗口上方浮出「已添加「A家」」「已获取 3 个模型。重启 ChatGPT 后生效。」；列表多出「A家」一行；Codex 模型列表里中转模型依次是「中转 · …」「A家 · …」；选「A家 · auto」发消息，请求发往 `relay2.example.com`。

**用例（边界 / 异常）**
- 场景：「A家」的服务暂时连不上，主窗口点「重试」后仍失败。预期：只有「A家」一行显示黄色「没更新，沿用上次的 3 个」和「重试」，其他配置照常，Codex 里「A家」的模型仍在。
- 场景：小周把「A家」改名为「备用线路」。预期：Codex 里显示名变成「备用线路 · …」；改名前用「A家 · auto」聊的对话继续发消息照常回复。
- 场景：小周删除「A家」。预期：确认后「A家」的模型从 Codex 列表消失；用它聊过的对话继续发消息，Codex 里显示「这个模型所在的中转配置已删除，请换一个模型。」

## 约束

- C1 中转配置由「名字、Base URL、API Key」组成，最少 1 个、最多 10 个，按添加顺序排列。所有配置同时生效。
- C2 名字：去掉首尾空格后 1~16 个字；不能含「·」；和已有配置的名字不区分大小写比较不能相同。不合规则时保存不成功，并在名字一栏下显示：「请填写名字。」「名字最多 16 个字，现在是 N 个。」「已有叫「X」的配置（不区分大小写），换一个名字。」「名字里不能有「·」。」超过 16 个字时允许继续输入，保存时报错。
- C3 Base URL、API Key 的校验和原来一样；为空时显示「请填写 Base URL。」「请填写 API Key。」；Base URL 不以 https:// 开头时显示「Base URL 要以 https:// 开头。」
- C4 每个配置的 API Key 单独保存在系统凭据库（macOS 钥匙串、Windows 凭据管理器）；删除配置时它的 Key 从凭据库删掉。名字和 Base URL 保存在本工具的设置里。
- C5 Codex 模型列表里，中转模型的显示名是「<配置名> · <模型>」，排在官方模型后面，按配置顺序、再按原来的模型顺序排列。
- C6 每个配置有一个用户看不到、不随名字变的内部编号；中转模型的内部名由这个编号和模型名组成。升级来的配置的模型内部名保持升级前的写法，所以升级前、改名前的对话都能继续。两个配置有同名模型（例如都有 auto）时各自独立出现，请求按内部名发往对应配置的 Base URL，并带对应配置的 Key。
- C7 升级：已有的那一个配置自动命名为「中转」，排第一；升级后 Codex 里原来的「中台 · <模型>」显示为「中转 · <模型>」。
- C8 「只用中转」方式下的默认模型：按配置顺序第一个有 auto 的配置的 auto；所有配置都没有 auto 时不指定默认模型。
- C9 添加、编辑用弹窗（宽 520px，头部 24px 应用图标加标题「添加配置」或「编辑配置」）。保存时先用填的 Base URL 和 Key 获取模型列表：成功才保存，弹窗关闭，主窗口浮出「已添加「名字」」「已获取 N 个模型。重启 ChatGPT 后生效。」或「已保存「名字」」「重启 ChatGPT 后生效。」；失败不保存，弹窗留着，弹窗上方浮出红色提示「没有保存」和原因（如「中转服务返回 401：API Key 无效或已过期。已填的内容都还在，改好后再保存。」）。保存中三栏和「取消」不可用，按钮显示「正在保存并获取模型…」。
- C10 删除：只剩 1 个时「删除」不可用，列表下写「至少保留一个配置。」；点「删除」弹出确认，标题「删除配置「名字」？」，正文写明 Codex 列表里不再有它的 N 个模型、API Key 会从系统凭据库删除、重启 ChatGPT 后生效，按钮「取消」「删除」；删除成功浮出「已删除「名字」」「重启 ChatGPT 后生效。」；写入设置失败浮出红色「没有删除「名字」」和原因，列表不变。
- C11 已删除配置的模型被请求时，请求不发往任何服务，返回给 Codex 的错误文字是「这个模型所在的中转配置已删除，请换一个模型。」
- C12 满 10 个时「添加配置」不可用，列表下写「已有 10 个，达到上限。」；其他时候写「已有 N 个，最多 10 个。」列表最多显示 3 行，更多时在列表内滚动。
- C13 每个配置一行（高 64px）：上面是名字，下面是状态和 Base URL（放不下用省略号），右边「编辑」「删除」。状态：
  - 正常：绿色对勾「N 个模型」；
  - 本次获取失败、有上次的列表：黄色「没更新，沿用上次的 N 个」，多一个「重试」按钮，Codex 里沿用上次的模型；
  - 从没获取成功：黄色「还没获取到模型」和「重试」，Codex 里没有它的模型；
  - 正在获取：转圈「正在获取…」，「编辑」「删除」不可用；
  - 转发关着：「转发关闭时不获取」。
  一个配置获取失败不影响其他配置。原来窗口顶部的「中转模型列表本次没有更新」「还没有获取到中转模型」两条全局提示不再出现。
- C14 获取时机和原来一样（打开转发、本工具启动且转发开着、保存配置、点「重试」），每次对所有配置分别获取；点某行的「重试」只获取这一个配置。
- C15 首次设置窗口多一栏「名字」，默认填好「中转」，规则同 C2；完成后进入只有这一个配置的主窗口。完成页文字：「设置完成，转发已开启」「已获取 N 个中转模型。…」其余按原有接入方式规则。

## 验收

- [ ] C1：添加到第 10 个后「添加配置」不可用；删到剩 1 个后「删除」不可用；Codex 列表里能同时看到所有配置的模型。
- [ ] C2：分别输入空、17 个字、「a家」（已有「A家」）、「中转·主力」→ 保存失败并显示对应文字；输入「  B家  」→ 保存为「B家」。
- [ ] C3：三种 Base URL / Key 错误显示对应文字。
- [ ] C4：添加 2 个配置后，系统凭据库里有 2 条本工具的 Key 条目，普通设置文件里搜不到 Key；删除其中一个后只剩 1 条。
- [ ] C5：3 个配置时，模型目录里中转模型的显示名和顺序与规定一致。
- [ ] C6：两个配置都有 auto → 目录里有两个不同内部名的 auto；分别用它们发请求，测试中转各自只收到发给自己的请求，带的是各自的 Key。改名后用改名前的内部名发请求，仍发往同一个配置。
- [ ] C7：用升级前的设置启动新版本 → 只有一个名为「中转」的配置，模型内部名和升级前相同，显示名为「中转 · <模型>」。
- [ ] C8：「只用中转」方式下：第一个配置有 auto → 默认它的 auto；第一个没有、第二个有 → 默认第二个的 auto；都没有 → Codex 配置里不写默认模型。
- [ ] C9：添加成功、编辑成功、获取失败三种情况的弹窗和提示与规定一致；失败时配置数不变。
- [ ] C10：删除确认和删除成功、失败的提示与规定一致。
- [ ] C11：删除一个配置后用它的模型发请求 → 不向任何服务发请求，Codex 收到规定文字。
- [ ] C12：配置数为 3、4、10 时列表下文字和滚动行为与规定一致。
- [ ] C13：五种状态的文字、颜色、按钮与规定一致；让一个测试中转失败，另两个照常，窗口顶部没有全局提示。
- [ ] C14：点某行「重试」只请求该配置的模型列表接口；打开转发时每个配置各请求一次。
- [ ] C15：首次设置窗口有「名字」栏，默认「中转」；完成后主窗口只有一个配置。

## 验证路径

1. 用两个测试中转（relay.example.com、relay2.example.com）添加两个配置 → 列表两行，重启 ChatGPT 后 Codex 里看到两组模型。
2. 分别用两组 auto 发消息 → 各自发往对应中转。
3. 停掉第二个测试中转，点它那行「重试」→ 只有那一行变黄，第一个配置照常。
4. 改名、删除第二个配置 → 显示名跟着变；删除后用它的旧对话发消息，收到规定错误文字。
