# 「中台」改称「中转」

## 用户故事

### P0：作为用户，我想看到一个通用、不带公司腔的称呼

**用例（主路径）**
- 场景：小周升级到新版本后打开主窗口。
- 操作：看主窗口、菜单栏菜单，打开官网。
- 预期：所有地方都写「中转」，例如「使用中转」「官方 + 中转」「只用中转」「中转配置」「中转模型」；找不到「中台」两个字。

## 约束

- C1 两端 App 的所有界面文字、提示、弹窗、菜单里，「中台」一律换成「中转」。下面几处按读起来通顺的写法改：
  - 开关、转发总览标题、菜单项「转发到中台」→「使用中转」；
  - 首次设置大标题「连接到中台」→「连接中转服务」；
  - 「填写中台提供的 Base URL 和 API Key」→「填写中转服务提供的 Base URL 和 API Key」；
  - 错误标题「没能连上中台」→「没能连上中转服务」；
  - 「请求未被中台接受」→「请求未被中转服务接受」，「连不上中台，请检查网络和 Base URL」→「连不上中转服务，请检查网络和 Base URL」。
- C2 「只用中转」方式下请求了非中转模型时，返回给 Codex 的错误文字是「当前没有登录 ChatGPT，官方模型不可用，请切换到中转模型。」；本工具返回给 Codex 的其他错误文字里的「中台」也换成「中转」。
- C3 Codex 模型目录里中转模型的说明文字（目录里的描述字段）不出现「中台」。
- C4 官网中文页里的「中台」全部换成「中转」（含首屏「这个页面把你自己的模型服务叫作「中转」。」）；英文页的 relay 不变；App 界面示意图里的文字同步换成新界面的写法。
- C5 README 里出现的「中台」换成「中转」。
- C6 「转发」作为功能名保留：提示和状态里的「转发已开启」「已打开转发」「转发关闭时不获取」等不改。
- C7 内部模型名的前缀 `relay-`、凭据库里的条目名、日志里的英文字段不变；升级前后的对话照常能继续。

## 验收

- [ ] C1：在 macOS、Windows 源码的界面文字和两端测试里搜「中台」，结果为 0；四处改写按规定。
- [ ] C2：「只用中转」方式下用官方模型名发请求 → 收到规定的错误文字。
- [ ] C3：生成的模型目录文件里搜「中台」，结果为 0。
- [ ] C4：官网文件里搜「中台」，结果为 0；中文首屏说明是规定的那一句。
- [ ] C5：README 里搜「中台」，结果为 0。
- [ ] C6：转发开、关时的提示仍写「转发」。
- [ ] C7：升级前用「中台 · auto」聊过的对话，升级后继续发消息能正常回复。

## 验证路径

1. 装新版本 → 主窗口、菜单、弹窗里都是「中转」。
2. 打开官网中文页 → 没有「中台」。
3. 打开一条升级前的对话继续发消息 → 正常回复。
