# 多中转配置与外观更新

## 背景与问题

- 本工具只能填一组 Base URL 和 API Key。手上有几家模型服务的用户只能来回改配置，没法在 Codex 里同时用；模型列表里都写「中台 · 」，看不出模型来自哪一家。
- 「中台」这个称呼太商务、太像公司内部用语，普通用户不容易理解。
- 主窗口三张卡片加大段说明文字，占的高度太多，第一眼抓不到转发开没开、用的哪种接入方式。
- 本工具没有应用图标：Finder、安装包、开始菜单里都是系统默认图标；菜单栏、托盘、官网三处的图形也不一样。

## 目标

- 用户可以添加最多 10 个中转配置并给每个命名，所有配置的模型同时出现在 Codex 里，显示为「<名字> · <模型>」。
- 所有用户看得到的地方把「中台」改称「中转」。
- 主窗口在 3 个配置时比"三张卡片加配置列表"的旧布局矮约 290px，接入方式的取值一眼可见。
- macOS 和 Windows 都有统一的应用图标，菜单栏、托盘换成同一图形的单色版。

## 非目标

- 不支持在多个配置之间做负载均衡、故障自动切换或按模型挑选配置；同名模型各自独立出现，由用户在 Codex 里选。
- 不提供配置的拖动排序、导入导出、启用/停用单个配置。
- 不改首次设置窗口、菜单栏菜单、弹窗的布局（只改其中的文字和图标）。
- 不做图标的商标查重和上架 App Store 的准备。

## 依赖与交付顺序

01 → 02 → 03；04 和其余并行。02 的配置卡片在 03 里填进多配置列表。

## 整体验证路径

1. 用升级前的设置启动新版本 → 主窗口是新布局，只有一个名为「中转」的配置，界面里没有「中台」二字；Codex 里模型显示为「中转 · …」，升级前的对话能继续。
2. 添加配置「A家」→ 浮出成功提示；重启 ChatGPT 后 Codex 里多出「A家 · …」模型，选它发消息正常回复。
3. 关掉「使用中转」→ 转发总览变白底、窗口变矮；再打开恢复。
4. 打包 dmg 和 Windows 安装程序 → 安装包、App、菜单栏、托盘都显示新图标。

## 决策记录

- 2026-11-16 用户提出「中转配置支持多个，并且可以给每个配置命名，命名不能重复，替换模型前面的中台两字显示」。质疑时给出更便宜的做法「只给现在这一个配置起名字」（约半天），用户选「同时生效，所有配置的模型一起出现」。否决「保存多个、同一时间只启用一个」：不能在 Codex 里同时看到两家。
- 2026-11-16 用户选定：升级时已有配置自动命名（当时定为「中台」，随后改称决定后变为「中转」）；名字 1~16 字、去首尾空格、不区分大小写判重、不能含「·」；「只用中转」默认选第一个有 auto 的配置的 auto（否决「让用户设默认配置」）；改名后旧对话照常继续（否决「内部名跟名字变」）；至少保留一个、删除前确认（否决「可以删光」）；最多 10 个（否决不设上限，原因是启动耗时和列表长度）；单个配置获取失败只影响自己（否决整体提示）。
- 2026-11-17 用户选定：重名提示改为「已有同名配置「X」。」——字段错误只占帮助文字那一行、弹窗高度不变，原句固定部分 23 个字，名字稍长就放不下；否决「已有同名配置「X」，换一个名字。」（macOS 实测名字 16 个字时还差约 19pt）和「……，请改名。」（余量只有约 4pt，Windows 字体略宽可能仍放不下）；否决「放不下显示省略号、悬停看全文」（键盘用户看不到「换一个名字」）和「错误行固定留两行高」（平时每栏多一行空白）；「同名」本身表达了大小写不同也算重复
- 2026-11-16 用户要求主窗口「重新设计布局和风格」，在三套方案（A 转发总览 + 卡片、B 系统设置式分组列表、C 左右两栏）里选了 A，没选推荐的 B。同意删掉开关下的「开启时，本助手按下方的接入方式修改 Codex 配置。」、缩短两种接入方式的说明、删掉"登录后点「重新检测」就能同时用官方模型"半句、取消「运行状态」卡片并入底部状态行。用户指出「接入方式」和「官方 + 中台」颜色一样抓不到重点，改为标签灰色、取值深色加粗。
- 2026-11-16 用户认为「中台」太商务，在「第三方」「自定义」「中转」里选了「中转」，范围是 App 两端、官网和文档。四处读着别扭的地方按建议改成「使用中转」「连接中转服务」「填写中转服务提供的…」「没能连上中转服务」。代价：老用户升级后 Codex 里的「中台 · auto」会变成「中转 · auto」。
- 2026-11-16 开关名改为「使用中转」后，提示和状态里的「转发」（如「转发已开启」「转发关闭时不获取」）保留不改：「转发」是这个功能的名字，开关名是动作说法，两者不冲突。由主对话定，用户读 PRD 时可推翻。
- 2026-11-16 添加或编辑时连不上中转或 Key 无效 → 不保存、弹窗留着（否决「照样保存，行内显示还没获取到模型」），和原来「没有保存」的行为一致；名字超过 16 字允许继续输入、保存时报错（否决输入框限长）；转发关闭时每行写「转发关闭时不获取」（否决显示上次的模型数）；首次设置窗口的说明文字不改，只加名字一栏。
- 2026-11-16 应用图标：用户在 A 双向箭头、B 拱桥、C 一分二、D 双拱桥墩四版里选了 A，没选推荐的 D。已告知 A 和苹果系统符号 `arrow.left.arrow.right.circle` 很像，苹果条款不许把系统符号或容易混淆的图形用作应用图标；本项目目前只通过 GitHub 分发。菜单栏、托盘两端都换成 A 的单色版（否决只换 Windows、都不换）；macOS 菜单栏 18px，Windows 托盘 16px 并跟随任务栏深浅换颜色。
- 本 PRD 改变了 2026-11-11.codex-model-bridge 里的这些行为：04/08 里主窗口「中台连接」「运行状态」卡片和「转发」卡片的布局与说明文字（08 C10、C12）；01、03、08 C11、C13 等处界面文字里的「中台」；02 里中转模型显示名「中台 · <模型>」；01 只能填一组 Base URL 和 Key；原来的全局提示「中台模型列表本次没有更新」「还没有获取到中台模型」。以本 PRD 为准。
