# 接入方式

## 用户故事

### P0：作为没有 ChatGPT 账号的用户，我想装好 Codex 后不登录、不填官方信息，只填中台的 Base URL 和 API Key 就能用中台模型

**用例（主路径）**
- 场景：小周在 Mac 上装好 ChatGPT 桌面版，从来没登录过；刚装好本工具并第一次打开。
- 操作：在「连接到中台」窗口填 Base URL `https://relay.example.com/v1`、API Key `sk-example-0000`，点「完成设置」，再点「完成」，自己重启 ChatGPT 后进入 Codex。
- 预期：完成页显示"设置完成，转发已开启"，并写明"没有检测到 ChatGPT 登录，接入方式为「只用中台」：Codex 不需要登录，模型列表里只有中台模型。"ChatGPT 重启后进入 Codex 不要求登录，模型选择器里只有「中台 · 」开头的模型，默认选中「中台 · auto」，发一条消息能正常回复。

**用例（边界 / 异常）**
- 场景：小周在「只用中台」方式下打开一个以前用官方模型聊过的对话，继续发消息。预期：请求不发往任何服务，Codex 里显示"当前没有登录 ChatGPT，官方模型不可用，请切换到中台模型。"
- 场景：小周后来注册并登录了 ChatGPT，ChatGPT 正在运行。操作：在主窗口点「重新检测」。预期：按钮显示"正在检测…"并禁用；随后直接切换，主窗口顶部浮出提示"已切换到「官方 + 中台」"，ChatGPT 不会被重启；用户自己重启 ChatGPT 后，Codex 里官方模型和中台模型都在。
- 场景：检测时 Codex 自己出错，既不是已登录也不是"Not logged in"。预期：接入方式保持上次的方式，主窗口顶部浮出黄色提示"没能检测 ChatGPT 登录状态"。

### P0：作为已登录 ChatGPT 的用户，我想继续同时使用官方模型和中台模型

**用例（主路径）**
- 场景：小林已登录 ChatGPT，第一次设置本工具。
- 操作：完成设置。
- 预期：完成页写明"已检测到 ChatGPT 登录，接入方式为「官方 + 中台」"；Codex 里官方模型在上、中台模型在下，和接入方式出现之前的行为一致。

**用例（边界 / 异常）**
- 场景：小林在 ChatGPT 里退出登录后，重新启动电脑；本工具随登录启动，ChatGPT 没在运行。预期：本工具检测到没登录，直接切换为「只用中台」，不弹窗；之后打开 ChatGPT，Codex 里只有中台模型。

## 约束

- C1 判断是否已登录的唯一办法：运行当前 ChatGPT 自带的 codex 程序的 `login status` 命令，使用用户平常的 Codex 数据目录。退出码为 0 → 已登录；退出码为 1 且输出恰好是 "Not logged in"，或以 "Error checking login status: failed to deserialize CLI auth from file:" 开头（在 ChatGPT 里退出登录后 Codex 登录文件留空时的输出）→ 没登录；其他情况（其他退出码、输出不同、找不到 codex 程序、10 秒内没有结束）→ 检测失败。命令的输出只用来做这一次比较，不保存、不写日志、不显示。
- C2 检测时机：本工具每次启动时、每次打开转发时（包括首次设置完成时）、用户点「重新检测」时。转发关闭时不检测。
- C3 接入方式只由检测结果决定，用户不能手动选择：已登录 →「官方 + 中台」；没登录 →「只用中台」；检测失败 → 打开转发时沿用上次检测成功时的方式，从没检测成功过就用「只用中台」；转发已经开着时（本工具启动、点「重新检测」）检测失败，不切换接入方式。
- C4 「官方 + 中台」方式下，Codex 配置、模型目录和请求分流的行为和接入方式出现之前完全一致。
- C5 「只用中台」方式下，本工具在 Codex 用户配置文件里写入：根上的 `model_provider = "modelbridge"`；`[model_providers.modelbridge]` 表，内容是名称"模型接入助手"、地址 `http://127.0.0.1:47311/v1`、接口格式 `responses`；根上的 `model_catalog_json`；中台有 `auto` 时根上的 `model = "relay-auto"`。不写 `openai_base_url`。配置文件里的其他内容一律不改。写入后，用同一份配置运行 Codex 的登录状态检查，得到的结果是"不需要 OpenAI 登录"。
- C6 「只用中台」方式下，模型目录里只有中台模型，每个中台模型的内部名、显示名、参数、思考等级和顺序都和「官方 + 中台」方式下目录里的中台部分相同。
- C7 「只用中台」方式下，请求里的模型不是本次显示的中台模型时，请求不发往任何服务，返回给 Codex 的错误文字是"当前没有登录 ChatGPT，官方模型不可用，请切换到中台模型。"
- C8 转发开着时，检测成功、且检测结果对应的接入方式和当前不同 → 直接切换，不弹窗，不重启 ChatGPT。ChatGPT 正在运行时，主窗口顶部浮出成功提示：切到「官方 + 中台」时标题"已切换到「官方 + 中台」"、正文"已检测到 ChatGPT 登录。重启 ChatGPT 后生效。"；切到「只用中台」时标题"已切换到「只用中台」"、正文"没有检测到 ChatGPT 登录。重启 ChatGPT 后生效。"。ChatGPT 没在运行时不提示。
- C9 切换接入方式后，Codex 配置文件的内容和"关闭转发、再按新方式打开转发"得到的内容逐字节一致；之后关闭转发，配置文件和第一次打开转发前逐字节一致。
- C10 主窗口「转发」区在转发开着时显示「接入方式」一行：方式名称，后面接"· 已检测到 ChatGPT 登录"或"· 没有检测到 ChatGPT 登录"（检测失败时接"· 沿用上次的方式"），右侧是「重新检测」按钮，下面一行说明：
  - 「官方 + 中台」："模型列表里官方模型在上，中台模型在下；选官方模型时仍然访问官方服务。"
  - 「只用中台」："不需要登录 ChatGPT。模型列表里只有中台模型，默认选中「中台 · auto」。登录 ChatGPT 后点「重新检测」，就能同时用官方模型。"
  - 转发关闭时不显示这一行。
- C11 点「重新检测」后，按钮变成"正在检测…"并禁用，直到检测结束。检测结果和当前方式相同 → 主窗口顶部浮出信息提示"接入方式没有变化"，正文写明当前检测结果（如"仍然没有检测到 ChatGPT 登录，继续只用中台模型。"）。检测失败 → 主窗口顶部浮出警告提示"没能检测 ChatGPT 登录状态"，正文"沿用上次的方式。可以稍后点「重新检测」再试。"
- C12 「转发到中台」开关下方的说明：开着时是"开启时，本助手按下方的接入方式修改 Codex 配置。"；关着时是"已关闭：Codex 配置已还原为开启前的样子。"
- C13 首次设置成功的完成页按检测结果显示：
  - 「只用中台」："已获取 N 个中台模型。没有检测到 ChatGPT 登录，接入方式为「只用中台」：Codex 不需要登录，模型列表里只有中台模型。"
  - 「官方 + 中台」："已获取 N 个中台模型。已检测到 ChatGPT 登录，接入方式为「官方 + 中台」。"
  - 两种都另起一行接着写"请重启 ChatGPT 后使用。助手会在你登录电脑时自动启动，在菜单栏里常驻。"（Windows 写"任务栏通知区域"）。下方只有一个「完成」按钮。
- C14 在一台从没登录过 ChatGPT 的电脑（或新建的系统用户）上，ChatGPT 桌面版不登录也能进入 Codex 模式，并用中台模型对话。

## 验收

- [ ] C1：分别准备已登录（退出码 0）、"Not logged in"（退出码 1）、登录文件为空时的 "Error checking login status: failed to deserialize CLI auth from file: …"（退出码 1，判为没登录）、其他输出的退出码 1、退出码 2、找不到程序、超过 10 秒不结束六种情况的假 codex 程序 → 判定依次为已登录、没登录、失败、失败、失败、失败；假程序的输出里放一个特殊字符串，这个字符串在日志、界面和本工具数据目录里都找不到。
- [ ] C2：工具启动、打开转发、点「重新检测」时各运行一次检测；转发关着时启动工具，检测没有运行。
- [ ] C3：检测结果为已登录 → 「官方 + 中台」；没登录 → 「只用中台」；先成功检测为「官方 + 中台」再检测失败 → 仍是「官方 + 中台」；从没检测成功过就失败 → 「只用中台」；转发开着、当前为「只用中台」、上次检测成功的结果是已登录，这次启动或「重新检测」检测失败 → 不切换，主窗口顶部浮出黄色提示。
- [ ] C4：已登录时打开转发，配置文件、模型目录和接入方式出现之前的版本生成的结果一致。
- [ ] C5：没登录时打开转发，配置文件里多了规定的几项，没有 `openai_base_url`，其他内容不变；用这份配置运行 Codex 后台服务查询登录状态，返回"不需要 OpenAI 登录"。
- [ ] C6：「只用中台」的模型目录里没有官方模型，中台条目和「官方 + 中台」目录里的中台部分逐项相同。
- [ ] C7：「只用中台」方式下用官方模型名发请求 → 没有向官方或中台发出任何请求，Codex 收到规定的错误文字。
- [ ] C8：转发开着、检测结果变化 → 直接切换，没有弹窗，ChatGPT 没有被重启；ChatGPT 运行时出现规定的成功提示，没运行时不提示。
- [ ] C9：「官方 + 中台」切到「只用中台」再切回，每次的配置文件都和关闭后按新方式重新打开的结果逐字节一致；最后关闭转发 → 和第一次打开前逐字节一致。
- [ ] C10：两种方式下主窗口「接入方式」一行的文字和说明与规定一致；转发关闭时这一行不存在。
- [ ] C11：点「重新检测」→ 按钮禁用并显示"正在检测…"；结果不变时浮出"接入方式没有变化"提示；检测失败时浮出规定的黄色提示。
- [ ] C12：开关开、关两种状态下，说明文字和规定一致。
- [ ] C13：没登录和已登录两种情况下完成首次设置，完成页文字和规定一致，只有「完成」一个按钮。
- [ ] C14：在新建的、从没登录过 ChatGPT 的 macOS 用户下安装 ChatGPT 和本工具并完成设置 → 进入 Codex 不要求登录，用「中台 · auto」发消息得到回复。

## 验证路径

1. 新建一个 macOS 用户，只装 ChatGPT，不登录；安装本工具并完成设置 → 完成页写明「只用中台」。
2. 自己重启 ChatGPT，进入 Codex → 不要求登录，选择器里只有中台模型，默认「中台 · auto」，发消息正常回复。
3. 查看 Codex 配置文件 → 有 `model_provider = "modelbridge"` 和对应的表，没有 `openai_base_url`。
4. 在 ChatGPT 里登录账号，回到本工具点「重新检测」→ 直接切换并浮出"已切换到「官方 + 中台」"；自己重启 ChatGPT 后，Codex 里官方模型和中台模型都在。
5. 关闭转发 → Codex 配置文件和第一次打开转发前逐字节一致。
