# 转发开关

## 用户故事

### P0：作为用户，我想用一个开关决定 Codex 走不走本工具，以便随时回到官方原样

**用例（主路径）**
- 场景：小林已开启转发，ChatGPT 正在运行，Codex 里有任务正在跑。
- 操作：在主窗口把「转发到中台」拨到关闭。
- 预期：弹窗"关闭转发并重启 ChatGPT？"，说明 Codex 里只会剩官方模型，重启会中断 Codex 当前任务。点「关闭并重启」后显示"正在还原 Codex 配置并重启 ChatGPT"。完成后开关显示"已关闭"，ChatGPT 重新打开，Codex 里只有官方模型，Codex 配置文件和打开转发前一致。

**用例（边界 / 异常）**
- 场景：ChatGPT 没在运行。操作：拨动开关。预期：不弹窗，直接写入或还原配置，也不打开 ChatGPT。
- 场景：弹窗里点「取消」。预期：开关保持原状态，配置不变。
- 场景：Codex 配置里原来有 `openai_base_url = "https://proxy.example.org/v1"`，不是本工具写的。操作：打开转发。预期：主窗口提示"已接管 Codex 原有的接入设置"，说明原值已备份、关闭时会还原。关闭转发后，这一行恢复为原值。
- 场景：转发开着时，用户手动把 Codex 配置里本工具写入的 `openai_base_url` 改成了别的值。操作：关闭转发。预期：本工具不改这一项，主窗口显示"没能自动还原 Codex 配置"，写明是哪一项、配置文件在哪，并提供「打开所在文件夹」和「重新检查」两个按钮。
- 场景：电脑上没装 ChatGPT，或者在当前 ChatGPT 版本里找不到它自带的 codex 程序。预期：开关保持关闭并且不能拨动，主窗口显示"没有找到 ChatGPT"和原因，并提供「重新检测」按钮。

## 约束

- C1 本工具在 Codex 用户配置文件里只写这几项，统称"接入项"：根上的 `openai_base_url`（指向本机转发服务）、`model_catalog_json`（指向本工具生成的合并模型目录）、`model`（中台有 `auto` 时才写）、`[desktop]` 表里的 `enabled-reasoning-efforts`（只追加中台模型需要、但列表里还没有的思考等级，用户原有的等级一个不删）。另外把根上的 `model_provider` 移除。配置文件里的其他内容一律不改，也不整份覆盖。配置文件在 macOS 上是 `~/.codex/config.toml`，在 Windows 上是 `%USERPROFILE%\.codex\config.toml`。
- C2 打开转发前，先记下这几项原来的值（没有就记"原来没有"）。配置里已有不是本工具写的同名项时，先备份原值再覆盖，主窗口显示"已接管 Codex 原有的接入设置"。
- C3 关闭转发时，把接入项逐项还原成打开前的值，原来没有的就删掉。还原后，接入项以外的内容和关闭前一致。
- C4 关闭转发或卸载时，如果某个接入项的当前值和本工具写入的值不一致，就不改这一项，其他接入项照常还原；主窗口显示"没能自动还原 Codex 配置"，写明是哪一项和配置文件的位置，提供「打开所在文件夹」和「重新检查」。用户点「重新检查」后重新判断一次。
- C5 写入或还原后，配置文件必须仍能被正常解析；写入过程中失败时，配置文件保持写入前的内容。
- C6 ChatGPT 正在运行时，打开或关闭转发都要先弹窗确认，说明重启会中断 Codex 里正在进行的任务。用户确认后才改配置并重启 ChatGPT，取消则什么都不改。
- C7 ChatGPT 没在运行时，拨动开关直接改配置，不弹窗，也不打开 ChatGPT。
- C8 没有找到 ChatGPT，或获取不到官方模型清单时，转发保持关闭，开关禁用，主窗口写明原因并提供「重新检测」。
- C9 首次安装前，整份备份当时的 Codex 配置文件，卸载后保留这份备份，方便用户手动对照。
- C10 转发状态会被记住，重启电脑后保持关闭前的状态。

## 验收

- [ ] C1：打开转发前后对比配置文件，只有上面列出的几项发生变化。
- [ ] C2：配置里预先放一个 `openai_base_url` 原值，打开转发后出现接管提示，备份里能看到原值。
- [ ] C3：打开再关闭转发，配置文件和打开前逐字节一致；中途手动加一行无关配置，关闭后这一行仍在。
- [ ] C4：转发开着时手动改掉 `openai_base_url` 再关闭 → 这一项保持手改后的值，其他接入项已还原，主窗口出现规定的提示和两个按钮；把这一项改回本工具写入的值后点「重新检查」→ 提示消失，这一项被还原。
- [ ] C5：写入过程中强制结束进程，配置文件仍是写入前的完整内容，能被正常解析。
- [ ] C6：ChatGPT 运行时拨动开关 → 出现确认弹窗；点「取消」→ 配置文件没有变化；点确认 → ChatGPT 被重启。
- [ ] C7：ChatGPT 没在运行时拨动开关 → 不弹窗，配置文件已改，ChatGPT 没有被打开。
- [ ] C8：在没装 ChatGPT 的系统上打开主窗口 → 开关禁用，并显示"没有找到 ChatGPT"。
- [ ] C9：安装后能找到安装前那份完整的配置备份，卸载后它仍然存在。
- [ ] C10：关闭转发后重启电脑 → 工具启动后转发仍是关闭的，配置没有被写入。

## 验证路径

1. 准备一份带自定义 `openai_base_url` 和其他无关设置的 Codex 配置。
2. 打开转发 → 出现接管提示；配置里只有接入项变了。
3. ChatGPT 运行中关闭转发 → 先弹窗确认，确认后重启；配置文件和第 1 步逐字节一致。
4. 再打开转发，手动改一个接入项后关闭 → 出现"没能自动还原"提示，被手改的那一项没被动过。
5. 在没有 ChatGPT 的环境里打开工具 → 开关禁用，显示原因。
