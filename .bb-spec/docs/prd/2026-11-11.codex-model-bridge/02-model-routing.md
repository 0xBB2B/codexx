# 模型分流

## 用户故事

### P0：作为用户，我想在 Codex 的模型选择器里同时看到官方模型和中台模型，以便只在 Codex 里切换模型

**用例（主路径）**
- 场景：小林已开启转发，测试中台可用模型是 `auto`、`deepseek-v3.2`、`qwen3-coder-plus`、`unknown-model-x`。内置参数表里有前三个，没有第四个。
- 操作：重启 ChatGPT，进入 Codex，打开模型选择器。
- 预期：先列出当前 ChatGPT 版本自带的官方模型，后面是 `auto`、`deepseek-v3.2`、`qwen3-coder-plus`；没有 `unknown-model-x`。默认选中的是 `auto`。

### P0：作为用户，我想选哪个模型请求就去哪里，以便官方模型照常用、中台模型也能用

**用例（主路径）**
- 场景：同上。
- 操作：用 `deepseek-v3.2` 发一条消息，再切到一个官方模型发一条消息。
- 预期：第一条请求到达中台，带的是中台 API Key，不带任何官方凭据；第二条请求到达官方服务，请求头和 Codex 发出的原样一致。两条消息都正常回复。

**用例（边界 / 异常）**
- 场景：中台 API Key 已失效。操作：用中台模型发消息。预期：Codex 里显示"中台服务返回 401：API Key 无效或已过期"，不显示中台返回的原文。切到官方模型后仍可正常使用。
- 场景：工具启动时拉取中台模型列表超时，上次成功获取的列表是 6 个模型。预期：Codex 里继续显示那 6 个中台模型。主窗口顶部提示"中台模型列表本次没有更新"，写明原因、上次获取时间，并提供「重试」按钮。
- 场景：首次拉取就失败。预期：Codex 里只显示官方模型；主窗口显示"还没有获取到中台模型"和原因，并提供「重试」按钮。

## 约束

- C1 本工具在本机提供一个转发服务，只接受来自本机（127.0.0.1 或 ::1）的连接，其他来源一律拒绝。
- C2 请求里的模型属于本次显示的中台模型时，转发到用户填的 Base URL。转发前清空原请求头，只保留 Accept、Content-Type、OpenAI-Beta、User-Agent 四个，再加上从系统凭据库读出的中台 API Key。官方的 Authorization、ChatGPT-Account-ID、Cookie 等一律不带。
- C3 其他请求转发到官方服务：带 ChatGPT-Account-ID 的到 `https://chatgpt.com/backend-api/codex`，不带的到 `https://api.openai.com/v1`。请求头不改。请求体只有一种情况会改：对话记录里有中台模型产生的加密推理内容，或本工具生成的压缩摘要。这时去掉加密推理内容，把压缩摘要换成普通文本，其余内容原样保留。不含这两类内容的请求，请求体逐字节不变。
- C16 发往中台的请求里，如果对话记录里有官方模型产生的加密推理内容，就先去掉它们再转发；可见的对话内容和工具调用记录都保留。这样同一个对话里在官方模型和中台模型之间来回切换，也不会报错。
- C17 中台模型的对话长到需要压缩时，本工具接管这一步：把 Codex 的压缩请求改成一次普通的"总结前面的对话"请求，发给同一个中台模型，再把总结结果作为压缩摘要交还给 Codex。之后的请求如果带着这份摘要，按普通文本发给中台。
- C18 中台模型不提供联网搜索等官方专有工具。Codex 用中台模型时，发给中台的请求里没有这些工具。
- C19 Codex 发来的请求体是压缩格式（Content-Encoding: zstd）时，本工具先解压再识别模型。转发给中台的是解压后的请求体，不带这个压缩标记；官方请求不涉及 C3 所说的改动时，保持原来的压缩格式转发。
- C4 本工具不保存、不记录官方凭据。日志和错误信息里不出现任何请求头的值。
- C5 本工具不读取 Codex 数据目录里的官方登录凭据文件 `auth.json`，也不复制它。
- C6 官方模型清单来自当前安装的 ChatGPT 自带的 codex 程序。获取时使用一个空的临时 Codex 数据目录，并清除 OPENAI_API_KEY、CODEX_API_KEY 环境变量。
- C7 中台模型 = 中台模型列表接口返回的模型，和内置参数表里的模型两边都有的部分。只在中台列表里、参数表里没有的模型不显示。参数表随工具版本发布，新增模型要发新版。
- C8 每个中台模型在模型目录里的上下文窗口、思考等级、是否支持图片输入，都取自内置参数表。
- C9 合并模型目录里，官方模型在前（顺序和 ChatGPT 自带清单一致），中台模型在后。
- C10 打开转发时，如果中台模型里有 `auto`，就把 Codex 默认模型设为 `auto`；没有就不改默认模型。
- C11 工具每次启动时，都重新获取官方清单和中台列表，重新生成合并模型目录。中台列表获取失败时，沿用上次成功获取的中台列表，主窗口显示原因、上次获取时间和「重试」按钮。从来没有成功获取过时，目录里只放官方模型，主窗口显示"还没有获取到中台模型"。
- C12 中台返回错误或连不上时，返回给 Codex 的错误只包含中性说明和状态码：401 →"API Key 无效或已过期"；403 →"API Key 没有权限"；404 →"Base URL 不正确"；429 →"请求太频繁，请稍后重试"；5xx →"中台服务暂时不可用"；超时或网络错误 →"连不上中台，请检查网络和 Base URL"。中台原文不转发，也不写日志。
- C13 Codex 发起 WebSocket 连接请求时，本工具返回 426，让 Codex 改用普通 HTTP 请求，这样才能按单个请求分流。
- C14 中台和官方的流式回复，按收到的顺序立即转给 Codex，不攒到最后一起发。
- C15 界面、日志、错误信息里不显示中台模型清单。主窗口只显示中台模型的数量。

## 验收

- [ ] C1：从另一台机器访问本工具的转发端口 → 被拒绝。
- [ ] C2：用中台模型发请求，测试中台记录到的请求头只有规定的 4 个加上中台 Key；没有 Authorization 原值，也没有 ChatGPT-Account-ID 和 Cookie。
- [ ] C3：带和不带 ChatGPT-Account-ID 的非中台请求，分别到达对应的官方地址，请求头逐字节一致；不含中台加密推理内容和压缩摘要时，请求体也逐字节一致。含有时，这两类内容按规定处理，其余内容不变。
- [ ] C16：先用官方模型聊一轮、再切到中台模型 → 中台收到的请求里没有官方的加密推理内容，可见对话都在，回复正常；再切回官方模型 → 回复正常。
- [ ] C17：中台模型对话触发压缩 → 测试中台收到的是一次普通的总结请求，请求里没有 `compaction_trigger`；Codex 拿到摘要后能继续对话。
- [ ] C18：用中台模型发请求，测试中台收到的工具列表里没有联网搜索等官方专有工具。
- [ ] C19：发送 zstd 压缩的中台模型请求 → 能正确识别模型，测试中台收到解压后的请求体，请求头里没有 Content-Encoding: zstd。发送 zstd 压缩、内容无需改动的官方请求 → 官方收到原样的压缩请求体。
- [ ] C4：发送带特殊标记的官方 Authorization 后，在工具的日志和数据目录里搜不到这个标记。
- [ ] C5：把 `auth.json` 的读取权限设为拒绝后，工具功能不受影响；用文件访问监控确认工具没有打开过 `auth.json`。
- [ ] C6：获取官方清单时，被调用的 codex 程序收到的 CODEX_HOME 指向一个空目录，环境变量里没有 OPENAI_API_KEY、CODEX_API_KEY。
- [ ] C7：测试中台返回参数表外的模型 `unknown-model-x` → 它不出现在模型目录里。
- [ ] C8：生成的目录里，中台模型的上下文窗口、思考等级、图片输入和参数表一致。
- [ ] C9：目录里官方模型在前，顺序和自带清单一致，中台模型排在所有官方模型之后。
- [ ] C10：中台列表有 `auto` → Codex 默认模型变成 `auto`；没有 `auto` → 默认模型保持打开转发前的值。
- [ ] C11：启动时让中台超时 → 目录里的中台模型和上次一致，主窗口出现带时间和「重试」按钮的提示；从没成功过就超时 → 目录里只有官方模型。
- [ ] C12：让测试中台返回带特殊字符串的 401、500 错误和超时 → Codex 收到的错误文字和规定一致，特殊字符串在 Codex 收到的内容和日志里都找不到。
- [ ] C13：向转发服务发起 WebSocket 连接请求 → 收到 426。
- [ ] C14：测试中台按每 500ms 一段发送流式回复 → Codex 端每段的到达间隔也约为 500ms。
- [ ] C15：界面文字、日志里找不到任何中台模型名；主窗口只显示"已获取 N 个"。

## 验证路径

1. 开启转发并重启 ChatGPT → 模型选择器里官方模型在前、中台模型在后，参数表外的模型不出现，默认选中 `auto`。
2. 用中台模型发消息 → 测试中台记录的请求头只有规定的几个加中台 Key。
3. 切到官方模型发消息 → 正常回复，官方请求原样到达官方地址。
4. 让测试中台返回 401 → Codex 显示中性错误；切到官方模型仍可用。
5. 断网后重启工具 → Codex 里中台模型仍是上次的列表，主窗口提示没有更新并可重试。
