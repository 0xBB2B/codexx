# 更新检查

## 用户故事

### P1：作为用户，我想知道本工具有没有新版本，以便及时拿到新增的模型支持和修复

**用例（主路径）**
- 场景：小林用的是 1.2.0，GitHub 上已经发布了 1.3.0。
- 操作：登录电脑，工具自动启动。
- 预期：菜单里的「检查更新」变成"发现新版本 1.3.0 · 打开下载页"；主窗口底部状态区显示"发现新版本 1.3.0"和「打开下载页」。点击后在默认浏览器里打开 1.3.0 的发布页。

**用例（边界 / 异常）**
- 场景：检查时没联网。预期：自动检查时不弹提示，菜单保持"检查更新"；手动点「检查更新」时，提示"暂时无法检查更新，请稍后再试"。
- 场景：已是最新版，用户手动点「检查更新」。预期：提示"已是最新版本"。

## 约束

- C1 工具启动后检查一次，之后在运行期间每 24 小时检查一次；菜单和主窗口底部都可以手动检查。
- C2 检查只访问本项目在 GitHub 公开的最新发布信息，请求里不带 Base URL、API Key 或任何用户信息。
- C3 发布的版本号比当前版本新时，菜单显示"发现新版本 X · 打开下载页"，主窗口底部显示"发现新版本 X"和「打开下载页」。点击后在默认浏览器里打开那个版本的发布页。
- C4 不自动下载、不自动安装；提示只针对本工具，不涉及 ChatGPT。
- C5 自动检查失败时不打扰用户；手动检查失败时显示"暂时无法检查更新，请稍后再试"；手动检查发现已是最新时显示"已是最新版本"。
- C6 草稿版和预发布版不算新版本。
- C7 退出工具后不再检查。

## 验收

- [ ] C1：启动后 1 分钟内有一次检查请求；把系统时间往后调 24 小时后又有一次；点「检查更新」立即发起一次。
- [ ] C2：抓包确认检查请求只发到 GitHub 的发布信息接口，请求里没有 Base URL、API Key 或用户信息。
- [ ] C3：模拟最新发布是 1.3.0，当前是 1.2.0 → 菜单和主窗口都显示新版提示，点击后打开 1.3.0 的发布页。
- [ ] C4：发现新版后，工具没有下载任何安装包，程序文件没有变化。
- [ ] C5：断网时自动检查 → 没有弹窗；断网时手动检查 → 显示规定的文字；已是最新时手动检查 → 显示"已是最新版本"。
- [ ] C6：GitHub 上最新的是 1.3.0-beta 预发布版 → 不提示新版。
- [ ] C7：退出后 24 小时内没有检查请求。

## 验证路径

1. 在 GitHub 测试仓库发布一个比当前高的版本 → 重启工具，菜单和主窗口都出现新版提示。
2. 点「打开下载页」→ 浏览器打开对应的发布页，工具本身没有变化。
3. 断网后手动检查 → 看到"暂时无法检查更新"。
