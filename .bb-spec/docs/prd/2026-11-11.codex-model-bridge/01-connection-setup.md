# 连接设置

## 用户故事

### P0：作为第一次安装的用户，我想只填 Base URL 和 API Key 就完成设置，以便马上在 Codex 里用中台模型

**用例（主路径）**
- 场景：小林在 Mac 上已登录 ChatGPT 桌面端，刚安装好本工具并第一次打开。
- 操作：在「连接到中台」窗口填 Base URL `https://relay.example.com/v1`、API Key `sk-example-0000`，点「完成设置」。
- 预期：按钮变成"正在连接中台…"并禁用。连接成功后显示"设置完成，转发已开启"，同时写明"已获取 N 个中台模型"和"助手会在你登录电脑时自动启动"，并提供「立即重启 ChatGPT」和「稍后自己重启」两个按钮。

**用例（边界 / 异常）**
- 场景：Base URL 填成 `relay.example.com`。操作：点「完成设置」。预期：不发起连接，输入框标红，下方显示"Base URL 要以 https:// 开头。"
- 场景：API Key 填错。操作：点「完成设置」。预期：窗口顶部显示"没能连上中台：中台服务返回 401：API Key 无效或已过期"，已填的内容都还在，可以改后重试。
- 场景：两个输入框都空着。操作：点「完成设置」。预期：两个输入框下方都显示必填提示，不发起连接。

### P0：作为已在用的用户，我想修改 Base URL 或 API Key，以便换账号或换地址后继续用

**用例（主路径）**
- 场景：小林换了新的 API Key，ChatGPT 正在运行。
- 操作：在主窗口的「中台连接」里填新 Key，点「保存修改」。
- 预期：按钮显示"正在保存并重新获取模型…"。获取成功且模型列表有变化时，弹窗"已保存，重启 ChatGPT 以更新模型列表？"，提供「稍后」和「立即重启」两个按钮。列表没变化时，显示"已保存，不需要重启 ChatGPT"。

**用例（边界 / 异常）**
- 场景：新 Key 无效。操作：点「保存修改」。预期：显示"没有保存"，并写明原因是中台返回 401；工具继续使用修改前的 Base URL 和 Key，输入框里保留用户填的新内容。

### P0：作为用户，我想让 API Key 只保存在系统凭据库里，以便不在任何普通文件里留下明文

**用例（主路径）**
- 场景：小林完成首次设置。
- 操作：在磁盘上全文搜索刚填的 API Key。
- 预期：除系统凭据库外，任何文件里都搜不到这个 Key。系统凭据库在 macOS 上是钥匙串（Keychain），在 Windows 上是凭据管理器（Credential Manager）。

## 约束

- C1 首次设置窗口只有 Base URL 和 API Key 两个输入项，都是必填，没有任何模型相关的输入或选项。
- C2 Base URL 不以 `https://` 开头时，不发起网络请求，在字段下方显示"Base URL 要以 https:// 开头。"
- C3 「完成设置」和「保存修改」都要先用填写的 Base URL 和 API Key 请求一次中台的模型列表。请求成功才保存并生效；请求失败时什么都不保存，工具继续使用原来的设置，输入框保留用户填的内容。
- C4 连接失败时，错误提示只包含中性说明和 HTTP 状态码，或者"连不上中台"，不包含中台返回的原文。状态码和说明的对应：401 →"API Key 无效或已过期"；403 →"API Key 没有权限"；404 →"Base URL 不正确"；429 →"请求太频繁，请稍后重试"；5xx →"中台服务暂时不可用"；超时或网络错误 →"连不上中台，请检查网络和 Base URL"。
- C5 API Key 只保存在系统凭据库里，不写入任何普通文件、日志、错误提示或安装包。Base URL 只保存在用户本机的工具配置里。
- C6 API Key 输入框默认遮蔽显示，旁边的显隐按钮可以切换显示。
- C7 首次设置成功后，转发自动开启，「登录时启动」默认开启。
- C8 保存修改成功后：如果重新获取的模型列表和之前不同，并且 ChatGPT 正在运行，就弹窗询问是否重启 ChatGPT。列表相同时，只提示"已保存，不需要重启 ChatGPT"。
- C9 连接中台期间，相关按钮禁用并显示正在做什么，不能重复提交。

## 验收

- [ ] C1：首次设置窗口只有 Base URL、API Key 两个输入框，界面上找不到任何模型相关文字或控件。
- [ ] C2：Base URL 填 `relay.example.com` 点「完成设置」，没有网络请求发出，字段下方出现规定的提示。
- [ ] C3：用一个返回 401 的测试中台点「完成设置」，工具配置和系统凭据库都没有新增内容；在已有设置上保存一个无效 Key，工具仍然用旧 Key 转发成功。
- [ ] C4：让测试中台分别返回 401、403、404、429、500、超时，界面显示的文字和规定一致；中台返回的错误正文里放一个特殊字符串，这个字符串在界面和日志里都找不到。
- [ ] C5：设置完成后全盘搜索 API Key，只能在系统凭据库里找到；日志文件和工具配置文件里都没有。
- [ ] C6：打开主窗口时 API Key 是遮蔽的；点显隐按钮后显示明文，再点一次恢复遮蔽。
- [ ] C7：首次设置成功后，主窗口转发开关为"已开启"，菜单里「登录时启动」已勾选。
- [ ] C8：保存后测试中台的模型列表多了一个模型，并且 ChatGPT 在运行 → 出现重启弹窗；列表不变 → 只显示"已保存，不需要重启 ChatGPT"。
- [ ] C9：连接过程中连点按钮，只发出一次请求。

## 验证路径

1. 首次打开工具 → 出现只有两个输入框的「连接到中台」窗口。
2. 填入格式错误的 Base URL → 看到字段错误，没有网络请求。
3. 填入正确地址和错误 Key → 看到 401 的中性提示，输入内容保留。
4. 改成正确 Key → 看到"设置完成，转发已开启"和中台模型数量。
5. 全盘搜索 Key → 只在系统凭据库里找到。
6. 在主窗口换一个能拉到更多模型的 Key 并保存 → 出现重启 ChatGPT 的弹窗。
