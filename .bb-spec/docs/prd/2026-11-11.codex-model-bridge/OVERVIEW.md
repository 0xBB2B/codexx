# 模型接入助手：在 Codex 里并列使用官方模型和中台模型

## 背景与问题

有中台账号的用户想在 ChatGPT 桌面端的 Codex 模式里直接用中台模型，同时官方账号的模型照常可用。现在没有现成工具，只能手改 Codex 配置文件。手改有三个痛点：
- 容易写错，写错后 Codex 里官方模型也用不了；
- API Key 要明文写在本机文件或环境变量里；
- 改完不好还原，用户不知道原来是什么样子。

Ollama 0.34 已经用"本机分流"做到了在官方模型旁边追加模型，证明这条路可行。但 Ollama 只接本机模型，不接远程中台。

## 目标

- 用户只填 Base URL 和 API Key，就能在 Codex 的模型列表里同时看到官方模型、中台模型和中台的 auto 模型，并在 Codex 里自由切换。
- 选官方模型时请求最终到官方服务，选中台模型时请求最终到中台服务。两边的凭据互不外泄。
- 打开、关闭转发和卸载时，Codex 配置能准确还原；用户自己的其他设置不受影响。
- macOS 和 Windows 都提供原生桌面体验和可双击运行的安装包，在 GitHub 发布版本即可自动打包。

## 非目标

- 不接 VS Code 扩展和 Codex 命令行，只服务 ChatGPT 桌面端里的 Codex 模式。
- 不提供模型设置：不能在工具里填写、添加、删除、选择模型，也不显示模型清单。
- 不下载、不部署本地模型。
- 不提供代理端口设置，不自动安装更新，不更新官方 ChatGPT。
- 不做 Chat Completions 等其他接口格式的转换（中台已确认完整支持 Responses API）。
- 不读取、不复用官方登录凭据文件。
- 不支持 Linux，也不支持 Intel 芯片的 Mac。
- 不承诺能防御同一台电脑上的高权限程序。

## 整体验证路径

1. 在装有 ChatGPT 桌面端、已登录官方账号的 macOS 电脑上双击安装包安装本工具 → 弹出「连接到中台」窗口。
2. 填入测试中台的 Base URL 和 API Key，点「完成设置」→ 显示"设置完成，转发已开启"，菜单栏出现本工具图标。
3. 点「立即重启 ChatGPT」，进入 Codex 打开模型选择器 → 官方模型和中台模型都在，默认选中中台 auto 模型。
4. 用中台模型发一条消息 → 正常回复；用中台抓包记录确认请求里没有官方凭据。
5. 切换到官方模型发一条消息 → 正常回复。
6. 注销后重新登录系统，不手动打开本工具，直接打开 ChatGPT → 中台模型和官方模型都能用。
7. 在菜单里关闭转发并确认重启 → Codex 里只剩官方模型，Codex 配置文件和安装前的备份内容一致。
8. 重新打开转发，从菜单选「卸载」并确认 → 菜单栏图标消失，系统钥匙串里没有本工具的 API Key，Codex 配置和安装前一致，ChatGPT 和聊天记录都在。
9. 在 Windows 电脑上重复 1～8，入口换成任务栏通知区域，凭据库换成凭据管理器。

## 决策记录

- **选本机分流，不选只在配置文件里加一个模型服务（provider）**：后者在 Codex 里是"切换服务"，不能让官方模型和中台模型并列出现。并列出现要求官方请求也先经过本工具，这是 Ollama 的做法（Ollama 源码 commit 8a89b76，`cmd/launch/codex_app.go:311-353`、`internal/proxy/codex_desktop.go:229`）。
- **不能照抄 Ollama 的一步**：Ollama 会复制官方登录凭据文件 `auth.json` 去获取官方模型清单（`codex_app.go:1602`），违反"不读取官方凭据"。改用 ChatGPT 自带 codex 程序的内置清单（`codex debug models --bundled`，配一个空的 Codex 数据目录），已在本机实测，可以在不碰凭据的情况下拿到 12 个官方模型。
- **官方模型清单只能用本地快照**：Codex 只允许把官方模型目录的远端地址设为 ChatGPT 自己的域名（Codex 源码 commit 5228d94，`codex-rs/model-provider-info/src/lib.rs:805-820`）。所以工具每次启动时都重新生成一次目录，尽量跟上 ChatGPT 的版本。
- **改为登录后自启**：原需求是"随 Codex 启动、不开机自启"。本机分流下，工具没在运行时官方模型也会失效，所以工具必须比 Codex 先运行。曾考虑用 Codex 的钩子（hooks）在开始对话时拉起工具：已实测桌面端会执行钩子，但需要用户先在 Codex 里信任一次，而且"Codex 会不会等钩子执行完再发请求"没有得到证明。最终用户决定改为登录后自启，菜单里可以关。
- **转发开关代替"安装即接入"**：用户可以随时关闭转发，让 Codex 配置回到原样，官方请求直接到官方服务。退出程序时也先还原，避免留下指向本机的配置。
- **模型参数来自内置参数表**：中台的模型列表接口每个模型只返回 created、id、object、owned_by、supported_endpoint_types 五个字段（已实测），没有上下文窗口、思考等级、是否支持图片。模型名直接写进开源代码有暴露中台身份的风险，所以只内置市面上主流公开模型的参数，可用模型从中台拉取后取交集。参数表里没有的模型不显示，因为参数错了会让 Codex 发出中台不支持的请求。
- **配置冲突时备份后接管**：用户 Codex 配置里已有别人写的同名设置时，先备份原值再覆盖，关闭转发或卸载时还原。
- **中台报错只显示中性文字和状态码**：中台原文可能带品牌或地址，违反开源项目的敏感信息要求。
- **没有代码签名证书**：安装包不签名，用户首次打开要手动放行。每次升级后，系统可能再弹窗询问本工具能否读取钥匙串里的 API Key，这是已知代价。
- **已知风险，接受**：本机任何普通程序只要访问本工具的本机转发服务，带上中台模型名，就能用掉用户的中台额度。只能限制为"仅接受本机连接"，无法根除。
- **已知风险，接受**：本方案依赖 Codex 没有公开承诺的行为（模型目录字段、请求头里区分账号类型的方式、内置 codex 程序的位置）。ChatGPT 更新后可能失效，需要发新版跟进。Ollama 写死的 codex 程序路径在当前 ChatGPT 版本里已经找不到，就是例子。
- **补充三处 Codex 机制（写 plan 时读源码发现）**：
  - 上下文压缩：本工具借用的是 Codex 的官方服务通道，这个服务被当作支持"远端压缩"（Codex 源码 commit fe2f185，`codex-rs/core/src/tasks/compact.rs:63`）。压缩时，Codex 会在请求里放 OpenAI 专有的 `compaction_trigger`，中台不认识它，所以由本工具改写成普通的总结请求（参照 Ollama `server/responses_compact.go:23-53`）。
  - 中途切换模型：加密推理内容只有生成它的一方能解开，所以转发前去掉对方解不开的部分（参照 Ollama `internal/proxy/codex_desktop_normalize.go:312-316`）。为此放宽了"官方请求逐字节原样"：只在请求里带着中台产生的内容时才改动。
  - 思考等级：桌面端靠 `[desktop] enabled-reasoning-efforts` 决定界面上显示哪些思考等级（参照 Ollama `cmd/launch/codex_app.go:387-483`），所以把它也列为接入项，只追加、不删除。
  - 曾考虑只对中台模型关掉远端压缩。但 Codex 只能按服务整体设置压缩能力，没法按模型单独设置，这条路走不通，所以否决。
- **最低系统版本**：macOS 13（菜单栏和登录启动用到的系统接口从这个版本开始提供），Windows 10，覆盖的用户最多。
- **界面按已确认原型自绘**（2026-11-11 用户决定）：写 09 时曾改为两端尽量用系统原生控件（原生菜单、NSAlert/TaskDialog、系统按钮与输入框），做完看实物后用户认为不好看，改回已确认原型第 2 版的自绘样式：286px 菜单面板、520px 弹窗、主色按钮、自绘输入框与开关，两端一致。否掉的做法：系统原生控件（外观与原型差距大，用户不满意）。
- **Windows 最低版本细化为 Windows 10 1809**（写 13 时 PM 决定）：.NET 程序声明的最低系统是 10.0.17763，安装包对齐到同一版本，避免在更早的 Win10 上装得上却打不开。
- **Windows 安装向导为英文**：构建机上的 Inno Setup 6.7.1 不带简体中文语言文件，安装向导用默认英文界面，自定义的中文提示保留。
- **PM 决定的细节**：中台模型排在官方模型之后；打开转发时把 Codex 默认模型设为中台 auto 模型，中台列表里没有 auto 模型时不改默认模型；本机转发服务启动失败时，在主窗口顶部显示错误提示条。
