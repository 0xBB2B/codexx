# 打包发布

## 用户故事

### P1：作为维护者，我想只推一个版本标签就自动出安装包并发布，以便版本号由标签决定、不用在本机手动打包

**用例（主路径）**
- 场景：维护者把改动合并到 main 后，在 main 的提交上打标签 `v1.3.0` 并推送到 GitHub。
- 操作：等待自动流程跑完。
- 预期：GitHub 上出现公开的 1.3.0 发布页，挂着 macOS 安装包和 Windows 安装包，发布说明列出上次发版以来的改动。安装包文件名里带版本号和平台，例如 `model-bridge-1.3.0-macos.dmg`、`model-bridge-1.3.0-windows-setup.exe`。

**用例（边界 / 异常）**
- 场景：测试或打包失败。预期：自动流程显示失败，GitHub 上看不到这个版本的发布页，也看不到残缺的安装包。
- 场景：标签打在功能分支的提交上，或标签格式不对（如 `v1.3`、`vtest`）。预期：自动流程显示失败，不建发布页。
- 场景：这个标签的发布页已经存在（比如重推同一个标签）。预期：自动流程显示失败，已有的发布页和安装包保持原样。
- 场景：推送 `v1.3.0-beta.1`。预期：发布页标为预发布版，已装正式版的用户收不到它的更新提示。
- 场景：普通用户下载 macOS 安装包，双击打开。预期：系统提示"无法验证开发者"；用户在"系统设置 > 隐私与安全性"里点"仍要打开"后，可以正常安装和使用。项目 README 写明这个放行步骤。

## 约束

- C1 推送以 `v` 开头的标签时触发自动流程。标签必须是 `v<主>.<次>.<修订>` 或 `v<主>.<次>.<修订>-<后缀>`（三段都是数字，后缀只含字母、数字和点），并且指向 main 分支上的提交；不满足时流程失败，不建发布页。
- C2 安装包文件名格式是 `model-bridge-<版本号>-macos.dmg` 和 `model-bridge-<版本号>-windows-setup.exe`，版本号和发布标签一致（去掉开头的 v）。
- C3 macOS 安装包只支持 Apple 芯片、macOS 13 及以上；Windows 安装包支持 64 位 Windows 10 1809 及以上。在更低的系统版本上，安装包提示"需要 macOS 13 或更高版本"或"需要 Windows 10 或更高版本"，不安装。
- C4 安装包双击就能安装。Windows 安装时不要求管理员权限；macOS 把程序拖进"应用程序"文件夹即可。安装后第一次打开时，显示「连接到中台」设置窗口。
- C5 自动流程配置、安装包、发布说明和自动流程日志里，不出现真实 Base URL、API Key、中台品牌或其他能看出服务身份的信息。
- C6 安装包没有代码签名。README 写明 macOS 和 Windows 首次打开时怎么放行。
- C7 工具显示的版本号和发布标签一致。
- C8 自动流程先建一个草稿发布页，两端测试、打包、上传安装包全部成功后才公开。任一步失败或被取消时，删掉本次建的草稿（标签保留），GitHub 上看不到残缺的发布页。这个标签的发布页已经存在时流程失败，不改动已有的发布页和安装包。
- C9 不带后缀的标签发成正式版；带后缀的标签发成预发布版。
- C10 发布说明由 GitHub 根据上次发版以来的改动自动生成。

## 验收

- [ ] C1：在 main 的提交上推 `v0.0.1` → 流程运行并发布；在功能分支的提交上推 `v0.0.0-gatecheck.1` → 流程失败，没有发布页；`v1.3`、`v1.3.0+build`、`vtest` 这类标签 → 流程失败，没有发布页。
- [ ] C2：安装包文件名和规定格式一致。
- [ ] C3：macOS 安装包在 Apple 芯片、macOS 13 的 Mac 上能运行，程序文件只包含 arm64 架构，程序声明的最低系统版本是 13.0；Windows 安装包在 64 位 Windows 10 1809 上能运行。在低于最低版本的系统上，安装时出现规定的提示。
- [ ] C4：在 Windows 普通用户账户里双击安装，全程没有管理员权限请求；两个平台安装后第一次打开，都显示「连接到中台」窗口。
- [ ] C5：在仓库、安装包解包后的全部文件和自动流程日志里，搜索测试用的 Base URL、Key 和品牌词，都搜不到。
- [ ] C6：README 里有两个平台首次打开时的放行步骤。
- [ ] C7：发布 `v1.3.0` 后，安装包里工具显示的版本号是 1.3.0。
- [ ] C8：流程运行中发布页是草稿；让 Windows 打包失败 → 流程结束后这个标签没有发布页；对已有发布页的标签重跑 → 流程失败，原发布页和两个安装包都还在。
- [ ] C9：推 `v0.0.1` → 发布页是正式版，且是"最新版"；推 `v0.0.2-beta.1` → 发布页标为预发布版，GitHub 的"最新版"仍是 0.0.1。
- [ ] C10：发布页的说明不是空的，列出了上次发版以来合并的改动。

## 验证路径

1. 合并到 main 后，在 main 的提交上推一个版本标签 → 自动流程运行完成，出现公开的发布页，挂着两个安装包，文件名符合规定。
2. 分别在 macOS 和 Windows 上下载、放行、双击安装 → 第一次打开显示设置窗口，版本号正确。
3. 解开安装包全文搜索敏感词 → 没有命中。
