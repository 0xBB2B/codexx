# 已登录时手动切到「只用中转」

## 背景与问题

- 用户反馈（2026-11-25）：已登录 ChatGPT、接入方式为「官方 + 中转」时，账号额度一用完，Codex 顶部出现横幅"你的使用额度已用完，将于 15:20 重置"，发送按钮变灰。选中中转模型、输入文字后照样发不出去。中转模型不消耗 ChatGPT 账号额度，却也跟着用不了。
- 原因：「官方 + 中转」方式下 Codex 用的仍是 ChatGPT 账号登录，ChatGPT 桌面版按账号锁住整个输入框，不看选的是哪个模型。ChatGPT 桌面版不开源，本工具改不了它的界面。
- 现在的规定：接入方式只由登录检测结果决定，已登录就是「官方 + 中转」，用户不能手动选（2026-11-11.codex-model-bridge 的 08-access-mode C3）。所以额度用完时，唯一的办法是在 ChatGPT 里退出登录，再在本工具点「重新检测」。
- 2026-11-25 实测：账号保持登录、额度用完时，把 Codex 配置手动改成「只用中转」方式写的几项，重启 ChatGPT 后新建对话：额度横幅消失，发送按钮可用，中转模型正常回复。

## 目标

- 已登录 ChatGPT 时，用户能在主窗口手动切到「只用中转」，账号额度用完时也能继续用中转模型。
- 手动选择一直保持，直到用户自己关掉；本工具重启、关掉再打开转发、重新检测都不会把它切回去。

## 非目标

- 不做额度用完时的自动切换，也不显示账号额度。
- 不替用户重启 ChatGPT。
- 不处理切换接入方式后旧对话接不上的问题。
- 没登录时的行为不变：仍然只能「只用中转」。

## 依赖与交付顺序

单一子需求，无依赖。

## 整体验证路径

1. 已登录 ChatGPT、转发开着、接入方式「官方 + 中转」：主窗口「接入方式」一行右边有「只用中转 · 已关闭」开关，可以点。
2. 打开开关：接入方式变成「只用中转 · 已检测到 ChatGPT 登录」，标题下的说明换成手动那一句；ChatGPT 在运行时浮出"已切换到「只用中转」"提示。Codex 配置和没登录时打开转发写入的内容一致。
3. 重启 ChatGPT、新建对话、选中转模型发消息：能收到回复；账号额度用完时也能发。
4. 退出并重新打开本工具、点「重新检测」、关掉再打开转发：接入方式始终是「只用中转」，开关保持「已开启」。
5. 关掉开关：回到「官方 + 中转」，浮出"已切换到「官方 + 中转」"提示；关掉转发后，Codex 配置和第一次打开转发前逐字节一致。

## 决策记录

- **质疑结论：值得做。** 已有的绕过办法是退出 ChatGPT 登录再点「重新检测」，但额度恢复后还要重新登录、再检测一次。用户选择做开关（2026-11-25）。
- **先实测再定方案。** 桌面版换成「只用中转」配置后能否解开输入框，查不到资料；2026-11-25 在用户机器上实测可以，才定下这个方向。
- **手动开关，打开后一直保持到用户自己关掉**（用户 2026-11-25 选定）。被否决的做法：本工具下次启动时自动恢复「官方 + 中转」——额度何时恢复只有用户知道（横幅上写着重置时间），自动切回会让额度还没恢复的用户再切一次。
- **不做额度用完时自动切换**（用户 2026-11-25 选定）。原因：切换后必须重启 ChatGPT 才生效，而本工具不替用户重启 ChatGPT，自动切换省不了这一步；额度信息由 ChatGPT 直接向官方查询，本工具很可能拿不到（推测，没有验证）。
- **没登录时开关禁用，但保留用户原来的开或关**（用户 2026-11-25 选定）。被否决的做法：没登录时显示「已关闭」，重新登录后回到「官方 + 中转」（会悄悄丢掉用户的选择）；没登录时不显示开关（卡片布局要跟着变）。
- **检测失败时，按上次检测成功的结果决定开关能不能用**（用户 2026-11-25 选定）。原因：检测偶尔失败时，额度用完的用户仍能切换。被否决：检测失败一律不能用。
- **切换提示保持 4 秒自动消失**（用户 2026-11-25 选定）。提醒新建对话的内容在提示里；被否决：提示一直停留到用户点 ✕（要改设计规范里提示条的通用规则）。
- **说明文字并进标题下面原有的那一行，卡片不加行**（用户 2026-11-25 看过原型后选定）；放不下时末尾用省略号，鼠标悬停显示全文。
- 本需求替换 2026-11-11.codex-model-bridge/08-access-mode 的 C3（接入方式只由检测结果决定、用户不能手动选择）和 C10、C12 里「只用中转」那句说明文字；C8 的自动切换只在用户没打开开关时发生。
