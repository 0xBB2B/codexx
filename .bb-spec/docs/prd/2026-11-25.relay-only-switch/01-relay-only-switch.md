# 「只用中转」开关

## 用户故事

### P0：作为已登录 ChatGPT 的用户，我想在账号额度用完时手动切到「只用中转」，以便继续用中转模型

**用例（主路径）**
- 场景：小林已登录 ChatGPT，转发开着，接入方式「官方 + 中转」。ChatGPT 账号额度用完，Codex 发送按钮变灰。中转配置名为「中转」，有 auto 模型。
- 操作：在主窗口「接入方式」一行点开「只用中转 · 已关闭」开关；自己重启 ChatGPT；新建对话，选「中转 · auto」发一条消息。
- 预期：开关变成「只用中转 · 已开启」；接入方式显示「只用中转 · 已检测到 ChatGPT 登录」；标题下的说明是「已登录 ChatGPT，手动选了只用中转。只有中转模型，默认选中「中转 · auto」。」；窗口上方浮出成功提示，标题「已切换到「只用中转」」，正文「重启 ChatGPT 后生效。重启后请新建对话：用「官方 + 中转」聊过的旧对话接不上。」。重启后 Codex 里没有额度横幅，发送按钮可用，消息正常回复。

**用例（边界 / 异常）**
- 场景：额度恢复后，小林关掉开关。预期：接入方式回到「官方 + 中转 · 已检测到 ChatGPT 登录」，浮出提示「已切换到「官方 + 中转」」，正文「重启 ChatGPT 后生效。重启后请新建对话：用「只用中转」聊过的旧对话接不上。」。
- 场景：开关开着，小林退出并重新打开本工具，或点「重新检测」，或关掉转发再打开。预期：接入方式始终是「只用中转」，开关保持「已开启」。
- 场景：开关开着，小林在 ChatGPT 里退出登录后点「重新检测」。预期：接入方式「只用中转 · 没有检测到 ChatGPT 登录」，开关灰着不能点，但仍写「只用中转 · 已开启」；重新登录、再点「重新检测」后，开关恢复可用，仍是「已开启」，接入方式仍是「只用中转」。
- 场景：写 Codex 配置失败。预期：窗口上方浮出错误提示，标题「没能切换接入方式」，正文「没能修改 Codex 配置，接入方式保持原样。请稍后再试。」；开关和接入方式保持切换前的样子，Codex 配置保持原样。

## 约束

- C1 转发开着时，「接入方式」一行从左到右是：「接入方式 <方式名称> <检测结果>」、「只用中转」开关、「重新检测」按钮，只排一行。开关旁边写「只用中转 · 已开启」或「只用中转 · 已关闭」。转发关着时没有这一行。转发卡片仍是两行，高度和加开关之前一样。
- C2 「只用中转」开关能不能点：最近一次检测结果是已登录 → 能点；没登录 → 不能点；检测失败 → 按上次检测成功的结果决定，从没检测成功过 → 不能点。正在检测时开关照常能点。不能点时开关保持用户原来的开或关。
- C3 接入方式由开关和检测结果一起决定：开关开着 → 「只用中转」，不管检测结果；开关关着 → 和现在一样按检测结果决定（已登录「官方 + 中转」，没登录「只用中转」，检测失败沿用上次检测成功时的方式）。开关开着时，检测结果变化不会自动切换接入方式，也不弹"已切换到…"的提示。
- C4 开关的开或关保存在本工具自己的数据里：本工具重启、关掉再打开转发后都保留，只有用户点开关才会改变。第一次使用时开关是关着的。
- C5 点开关切换接入方式后，Codex 配置文件的内容和"关闭转发、再按新方式打开转发"得到的内容逐字节一致；之后关闭转发，配置文件和第一次打开转发前逐字节一致。本工具不重启 ChatGPT。
- C6 标题下的说明文字（转发开着时）只占一行，放不下时末尾用省略号截断，鼠标悬停显示全文。按情况写：
  - 「官方 + 中转」：「官方模型在上，中转模型在下；选官方模型时仍访问官方服务。」
  - 已登录、开关开着：「已登录 ChatGPT，手动选了只用中转。只有中转模型，默认选中「<配置名> · auto」。」
  - 没有检测到登录：「没有登录 ChatGPT，只能用中转模型，默认选中「<配置名> · auto」。登录后才能改接入方式。」
  - 后两种在所有配置都没有 auto 时，把「默认选中「<配置名> · auto」」换成「没有默认选中的模型」。
  - 检测失败时，按 C3 定出的接入方式和 C2 用的登录状态套用上面三句。
- C7 点开关切换成功、ChatGPT 正在运行时，窗口上方浮出成功提示，4 秒后自动消失，可以点 ✕ 关掉：
  - 切到只用中转：标题「已切换到「只用中转」」，正文「重启 ChatGPT 后生效。重启后请新建对话：用「官方 + 中转」聊过的旧对话接不上。」
  - 切回官方 + 中转：标题「已切换到「官方 + 中转」」，正文「重启 ChatGPT 后生效。重启后请新建对话：用「只用中转」聊过的旧对话接不上。」
  - ChatGPT 没在运行时不弹提示。
- C8 点开关后写 Codex 配置失败：窗口上方浮出错误提示，标题「没能切换接入方式」，正文「没能修改 Codex 配置，接入方式保持原样。请稍后再试。」，不自动消失，之后点开关切换成功时这条错误提示消失；开关、接入方式和 Codex 配置都保持切换前的样子。
- C9 开关开着、已检测到登录时点「重新检测」，结果仍是已登录：浮出信息提示，标题「接入方式没有变化」，正文「仍然检测到 ChatGPT 登录。你手动选了只用中转，继续只用中转模型。」。
- C10 键盘：Tab 顺序是转发开关 →「只用中转」开关（不能点时跳过）→「重新检测」。开关读屏名称为「只用中转」，并关联标题下的说明文字。
- C11 macOS 和 Windows 两端的文字、状态和行为一致。

## 验收

- [ ] C1：转发开着时「接入方式」一行依次是接入方式、「只用中转 · 已关闭」开关、「重新检测」，只排一行；转发卡片高度和改之前一样；转发关着时这一行不存在。
- [ ] C2：检测结果为已登录 → 开关能点；没登录 → 不能点；先检测为已登录、再检测失败 → 能点；从没检测成功过就失败 → 不能点；开关开着时检测为没登录 → 不能点且仍显示「已开启」；正在检测时开关能点。
- [ ] C3：已登录、开关开着 → 接入方式「只用中转」；开关开着时检测结果从已登录变成没登录、再变回已登录 → 接入方式一直是「只用中转」，没有弹"已切换到…"提示；开关关着时已登录 →「官方 + 中转」，没登录 →「只用中转」。
- [ ] C4：打开开关后退出并重新打开本工具 → 仍是「已开启」，接入方式「只用中转」；关掉转发再打开 → 同样；全新安装时开关是「已关闭」。
- [ ] C5：已登录时打开开关，Codex 配置和"关闭转发、按只用中转方式打开转发"的结果逐字节一致；再关掉开关，和按官方 + 中转方式打开的结果逐字节一致；最后关闭转发，和第一次打开转发前逐字节一致；全程没有重启 ChatGPT。
- [ ] C6：三种情况的说明文字和规定一致；所有配置都没有 auto 时换成「没有默认选中的模型」；配置名为 16 个字时说明只占一行、末尾是省略号，悬停显示全文。
- [ ] C7：ChatGPT 运行时打开开关、关掉开关，分别浮出规定的两条成功提示，4 秒后消失；ChatGPT 没运行时不弹提示。
- [ ] C8：让 Codex 配置写入失败后点开关 → 浮出规定的错误提示且不自动消失；开关、接入方式显示切换前的样子，Codex 配置文件和点开关前逐字节一致；接着让写入恢复正常再点开关切换成功 → 错误提示消失，只剩成功提示。
- [ ] C9：已登录、开关开着时点「重新检测」→ 浮出规定的「接入方式没有变化」提示。
- [ ] C10：Tab 依次聚焦转发开关、「只用中转」开关、「重新检测」；开关不能点时 Tab 从转发开关直接到「重新检测」；读屏读出「只用中转」和说明文字。
- [ ] C11：在 macOS 和 Windows 上分别走一遍 C1～C10，文字和行为相同。

## 验证路径

1. 已登录 ChatGPT，打开转发 → 「接入方式」一行显示「官方 + 中转 · 已检测到 ChatGPT 登录」和「只用中转 · 已关闭」开关。
2. ChatGPT 运行中，打开开关 → 浮出「已切换到「只用中转」」提示；说明文字换成手动那一句；Codex 配置里有 `model_provider = "modelbridge"` 和对应的表，没有 `openai_base_url`。
3. 重启 ChatGPT，新建对话，选中转 auto 模型发消息 → 正常回复。
4. 退出并重新打开本工具，点「重新检测」→ 仍是「只用中转」，浮出「接入方式没有变化」提示。
5. 关掉开关 → 浮出「已切换到「官方 + 中转」」提示；关闭转发 → Codex 配置和第一次打开转发前逐字节一致。
