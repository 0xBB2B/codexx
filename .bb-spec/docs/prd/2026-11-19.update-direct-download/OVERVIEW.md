# 新版本直接下载安装包

## 背景与问题
助手发现新版本后，菜单里的「发现新版本 X」和主窗口底部的「新版本 X」按钮点了会在浏览器里打开 GitHub 发布页。用户还要在发布页上自己找、自己挑本平台的安装包（macOS 的 .dmg 或 Windows 的 -windows-setup.exe），多一步，也可能下错。官网的下载按钮已经是点了直接下载安装包，助手里的提示和它不一致。

## 目标
- 点新版本提示后，浏览器直接开始下载本平台的安装包，中间不显示网页。
- 发布信息里没有本平台安装包时，提示仍然能用：改为打开发布页，文字也跟着写「打开下载页」。

## 非目标
- 助手自己下载、显示进度、自动打开或安装安装包。
- 改检查新版本的时机、频率和判断新旧的规则。
- 在助手里显示发布说明（这版改了什么）。
- 改官网的下载按钮。

## 依赖与交付顺序
单一子需求，无依赖。

## 整体验证路径
1. 在 macOS 上装 0.1.1，GitHub 上最新正式版是 0.1.2 且附件里有 `model-bridge-0.1.2-macos.dmg` → 菜单更新项显示「发现新版本 0.1.2」和副标题「下载安装包」→ 点它 → 浏览器把 `model-bridge-0.1.2-macos.dmg` 下载到「下载」文件夹，没有打开任何网页。
2. 在 Windows 上重复第 1 步 → 下载的是 `model-bridge-0.1.2-windows-setup.exe`。
3. 让最新发布的附件里没有本平台安装包 → 副标题写「打开下载页」→ 点它 → 浏览器打开 0.1.2 的发布页。

## 决策记录
- **2026-11-19 用户提出、用户确认**：点新版本提示改为直接下载本平台安装包，"类似于官网的下载方式，不要再做网页跳转"。替代了 2026-11-11.codex-model-bridge/06-update-check 里"点击后在默认浏览器里打开那个版本的发布页"的行为。
- **用默认浏览器打开安装包直链**（用户选）：和官网一样，浏览器直接把文件存到「下载」文件夹，助手自己不下载、不安装，原 06 C4"不自动下载、不自动安装"仍成立。否掉了"助手自己下载并显示进度、下完自动打开"：要新增进度界面、失败重试和文件校验，工作量约 5 倍，用户这次要的只是少掉找文件那一步。
- **下载地址取自发布信息的附件清单，找不到本平台安装包时退回发布页**（用户选）：地址来自 GitHub 实际给出的附件，文件一定存在；以后某一版漏传安装包时提示仍可用。否掉了"按命名规则拼地址"（漏传或改名时会下到 404 页面），否掉了"没有本平台安装包就不提示新版"（用户会错过新版）。本平台安装包按发版流程的文件名认：`model-bridge-<版本>-macos.dmg`、`model-bridge-<版本>-windows-setup.exe`。
- **文字用「下载安装包」，不写平台名**（用户看原型后选 A）：用户本来就在这个平台上，平台名是多余信息，两端一套文字。否掉了按平台写「下载 macOS 版 / 下载 Windows 版」。
- **退回发布页时文字写回「打开下载页」**（用户选）：文字和点了之后的实际动作一致。否掉了"一直写下载安装包"（点了看到的是网页，对不上）。
- **质疑结论**：值得做，改动小，路径和官网一致；代价是用户不经过发布页，看不到发布说明，已列入非目标。
