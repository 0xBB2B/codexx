# 换账号后官方模型跟上账号

## 背景与问题
用户会在 Go、Plus 等不同等级的 ChatGPT 账号之间切换，不同等级能用的官方模型不一样。转发开着时，Codex 只认本工具交给它的合并模型目录，不再自己向 OpenAI 要模型列表，它的模型缓存文件 `models_cache.json` 也就不再更新（openai/codex 源码 `codex-rs/model-provider/src/provider.rs:730-735`：配置了 `model_catalog_json` 就改用固定清单；`codex-rs/models-manager/src/manager.rs:1113-1140`：固定清单不联网）。本工具的官方模型又是按这个缓存文件过滤出来的，所以换账号后模型选择器里还是旧账号的模型，选到新账号用不了的就报「此模型不可用」。现在只能手动「关转发 → 换账号 → 重启 ChatGPT → 再开转发」绕过去。用户 2026-11-27 原话："现在需要先还原，再换账号重启之后才是新的官方模型"。

## 目标
- 转发开着、「官方 + 中转」方式下换了 ChatGPT 账号，不用关转发，最多一次对话之后合并模型目录里的官方模型就换成新账号能用的模型。
- 同一个账号升降级，最多 1 小时后跟上。
- 官方模型变了时，主窗口留一条提示，告诉用户重启 ChatGPT 后生效。

## 非目标
- 不管用 API Key 登录 Codex 的情况：它的官方模型仍按 `models_cache.json` 过滤。
- 「只用中转」方式下不查（这时没有官方模型，也没有官方请求经过本工具）。
- 不自动重启 ChatGPT，不改 Codex 配置里用户选中的 `model`。
- 不增加系统通知。
- 查列表失败时不提示用户。

## 整体验证路径
1. 转发开着、「官方 + 中转」方式，ChatGPT 登录 Plus 账号，在 Codex 里发一条消息 → 合并模型目录里的官方模型等于 Plus 账号的模型列表，没有新提示（和原来一样时）或出现「官方模型已按当前账号更新」（和原来不一样时）。
2. 在 ChatGPT 里换成 Go 账号，在 Codex 里发一条消息 → 合并模型目录里的官方模型换成 Go 账号的模型；主窗口左上角出现「官方模型已按当前账号更新」「重启 ChatGPT 后生效。」，过 4 秒仍在。
3. 重启 ChatGPT → 模型选择器里只有 Go 账号能用的官方模型，选任何一个都能正常对话。
4. 退出再打开本工具，先不发消息 → 合并模型目录里的官方模型仍是 Go 账号的；主窗口没有这条提示。
5. 关掉转发 → 这条提示（如果还在）一起消失。

## 决策记录
- **质疑结论：值得做**（2026-11-27）。用户自己在 Go 和 Plus 之间切换，每次都遇到「此模型不可用」，手动绕要 4 步还要重启两次。被否决的替代：只在界面上写清手动步骤（用户 2026-11-27 否决：每次换账号都要手动做）。
- **原定修法作废：定时看 `models_cache.json` 有没有变**（用户 2026-11-27 先选了它）。实验和 Codex 源码都证明转发开着时这个文件根本不会变（见背景），所以改成本工具自己查。
- **本工具用转发中的官方凭据向官方服务查账号模型列表**（用户 2026-11-27 选定）。原因：转发开着时只有本工具能拿到当前账号的信息（官方请求本来就经过本机转发服务，请求头原样转发，`core/internal/proxy/route.go:81-95`）；判断登录只许用 `login status` 的退出码和固定几句输出，拿不到账号等级。代价：本工具会用用户的凭据主动多发请求，所以改写了 AGENTS.md 里官方凭据那一条，只放开这一种请求，只发官方、不保存、不写日志。
- **什么时候查：本工具启动后第一次官方请求、账号变了、或离上次查超过 1 小时**（用户 2026-11-27 选定）。被否决：只在换账号时查（同账号升降级要等本工具重启才发现）；每次官方请求都查（官方请求量翻倍）。
- **只管 ChatGPT 账号登录**（用户 2026-11-27 选定）。原因：API Key 登录的请求不带账号标识，官方返回的模型列表格式也不同，不按账号等级区分。
- **查失败不提示、清单保持原样**（用户 2026-11-27 选定）。原因：失败不影响正常对话，提示只会打扰；到下一个查询时机再试。
- **把查到的模型名存下来，本工具重启后先用它**（用户 2026-11-27 选定）。只存模型名，不存凭据和账号标识。被否决：重启后退回 `models_cache.json`（它可能还是旧账号的，会先退回旧列表、等下一次请求又变回来，多弹一次提示）。
- **主窗口提示条，不自动消失，关转发时一起去掉**（用户 2026-11-27 看原型选定）。原因：变化多半发生在用户在 ChatGPT 里聊天时，主窗口多半没打开，4 秒消失就看不到；转发关掉后清单已还原，这句提示不再成立。这是成功提示「4 秒自动消失」规则的唯一例外（替换 `2026-11-26.notice-position` 里"成功和信息 4 秒自动消失"不带例外的说法），DESIGN.md 已同步。被否决：加系统通知（要申请通知权限，工作量多约半天）；和其他成功提示一样 4 秒消失。
- **文案**：标题「官方模型已按当前账号更新」，正文「重启 ChatGPT 后生效。」（用户 2026-11-27 选定）。被否决：「已按当前账号更新官方模型」。
