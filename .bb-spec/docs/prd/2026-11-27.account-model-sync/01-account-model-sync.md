# 跟随账号更新官方模型

## 用户故事
### P0：作为在 Go 和 Plus 账号之间切换的用户，我想要换账号后 Codex 里的官方模型自动换成新账号能用的，以便不再选到「此模型不可用」的模型

**用例（主路径）**
- 场景：转发开着，「官方 + 中转」方式，ChatGPT 登录 Plus 账号，合并模型目录里有 12 个官方模型。
- 操作：在 ChatGPT 里退出，登录 Go 账号，在 Codex 里发一条消息。
- 预期：本工具向官方服务查到 Go 账号的模型列表（5 个模型名）；合并模型目录里的官方模型换成这 5 个里 ChatGPT 自带清单也有的那些；主窗口左上角出现成功提示「官方模型已按当前账号更新」，正文「重启 ChatGPT 后生效。」；这条消息本身照常发往官方服务、正常返回。

**用例（边界 / 异常）**
- 场景：同一个 Plus 账号，离上次查不到 1 小时，又发了 10 条消息。
- 预期：本工具不再查，官方请求数量和不开转发时一样。
- 场景：查列表时官方服务返回 500，或断网。
- 预期：合并模型目录不变，不出任何提示，这条消息照常转发；1 小时后有官方请求时再查。
- 场景：用 API Key 登录 Codex（请求不带账号标识）。
- 预期：不查，官方模型仍按 `models_cache.json` 过滤。

### P0：作为用户，我想要知道清单换了要重启 ChatGPT，以便及时生效

**用例（主路径）**
- 场景：官方模型刚换成 Go 账号的，主窗口没开。
- 操作：过了 10 分钟打开主窗口。
- 预期：提示「官方模型已按当前账号更新」还在左上角；点 ✕ 后消失。

**用例（边界）**
- 场景：这条提示还在，用户又保存了中转配置「中转」。
- 预期：这条提示在上，「已保存「中转」」在下面 8px；4 秒后「已保存「中转」」消失，这条提示留在原位。
- 场景：这条提示还在，用户关掉转发。
- 预期：这条提示一起消失。

## 约束
1. 只在「官方 + 中转」方式下、经本机转发服务的官方请求带账号标识（`ChatGPT-Account-ID` 请求头）时查账号模型列表；请求不带账号标识、「只用中转」方式、转发关着时都不查。
2. 查询时机：本工具启动后第一个带账号标识的官方请求；账号标识和上次查时不同；离上次查（不论成败）超过 1 小时。三者都不满足时不查。同一时间最多只有一个查询在进行。
3. 查询只发往官方服务，用的是正在转发的这个请求带的官方凭据；凭据只在这次查询里用，不写进任何文件，不写进日志，不发往中转服务。账号标识不写进任何文件和日志。
4. 查询不拖慢原请求：原请求照常转发，转发结果和不查时一样。
5. 查到的模型名单和 ChatGPT 自带清单取交集，作为合并模型目录里的官方模型；交集为空、查询失败（网络错误、非 2xx、返回内容看不懂）时，合并模型目录不变，不提示。
6. 新的官方模型和合并模型目录里现有的官方模型不同时，重建合并模型目录，并在主窗口加一条成功提示：标题「官方模型已按当前账号更新」，正文「重启 ChatGPT 后生效。」，没有操作按钮。相同时不重建、不提示。
7. 这条提示不自动消失，点 ✕ 后消失；关掉转发时一起消失；同时最多一条，新的替换旧的、位置不变。和其他提示叠放时按出现先后从上往下排、间距 8。
8. 查到的模型名单（只有模型名）存进本工具自己的数据目录；本工具重启后、新的查询成功之前，用存下的名单过滤官方模型；从没查到过时按 `models_cache.json` 过滤（现有行为）。
9. 本工具重启后用存下的名单生成清单时不出这条提示。

## 验收
- [ ] 带账号标识的官方请求在启动后第一次经过时查一次；不带账号标识的请求、「只用中转」方式下的请求都不触发查询（约束 1）
- [ ] 账号标识变了立即查；同一账号 1 小时内不再查；超过 1 小时再来请求时查；上次查失败也按 1 小时算；并发的多个官方请求同时满足条件时只查一次（约束 2）
- [ ] 查询发往官方服务地址、带原请求的官方凭据；本工具写的所有文件和日志里都找不到凭据和账号标识；中转服务收不到这个查询（约束 3）
- [ ] 查询慢（如 5 秒）或失败时，原请求的响应和不查时一样，不被推迟（约束 4）
- [ ] 查到的名单和自带清单取交集写进合并模型目录；交集为空、500、断网、返回非 JSON 时目录不变、没有提示（约束 5）
- [ ] 名单变了：目录重建，主窗口出现标题「官方模型已按当前账号更新」、正文「重启 ChatGPT 后生效。」、没有按钮的成功提示；名单没变：目录文件不改写，没有提示（约束 6）
- [ ] 提示 4 秒后仍在；点 ✕ 消失；关转发时消失；连续两次变化只有一条；和「已保存「中转」」叠放时它在上、间距 8，后者 4 秒消失后它不动（约束 7）
- [ ] 查到的名单存在本工具数据目录，文件里只有模型名；重启本工具后没有新查询时，官方模型按存下的名单过滤；从没查到过时按 `models_cache.json` 过滤（约束 8）
- [ ] 重启本工具后主窗口没有这条提示（约束 9）
- [ ] macOS 和 Windows 两端提示条的样子、位置、去留一致，不盖住任何按钮和开关（约束 6、7）

## 验证路径
1. 准备一个假的官方服务：按账号标识返回不同的模型列表。转发开着、「官方 + 中转」方式。
2. 发一个带账号标识 A 的官方请求 → 假官方服务收到一次查询（带原凭据）和原请求；合并模型目录的官方模型等于 A 的名单和自带清单的交集；名单变了时主窗口出现提示。
3. 1 小时内再发 A 的请求 → 没有新查询。
4. 发账号标识 B 的请求 → 立即查询；目录换成 B 的；提示仍只有一条。
5. 让假官方服务对查询返回 500，换回 A 发请求 → 原请求正常返回，目录不变，没有新提示。
6. 搜本工具的数据目录和日志 → 没有凭据和账号标识，只有模型名单文件。
7. 重启本工具 → 目录官方模型仍是上次成功查到的；没有提示。
8. 关转发 → 提示消失。
