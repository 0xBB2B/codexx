# 窗口加宽到 760px

## 背景与问题

- 主窗口宽 620px，底部状态区一行要放 5 项：版本号、运行状态、ChatGPT 检测结果、中转模型数、「检查更新」。2026-11-19 用户装上 `0.1.0-local` 版本后截图反馈"有点挤"：版本号挤成「v0.1.0- / local」两行，「检查更新」挤成「检查 / 更新」两行。
- 有新版本时，最右边原来要放「发现新版本 X」加「打开下载页」两段，比「检查更新」多出约 121px，会更挤。
- 2026-11-19 在原型里实测（macOS 字体）：有新版本时，状态区一行最少要 732px；文字最长时最少要 828px。这种情况是后台服务停止、ChatGPT 版本暂不支持、同时有新版本。
- Windows 主窗口能被拖窄到 450px，拖窄后状态区左边那一组的尾部会被裁掉。

## 目标

- macOS 和 Windows 的主窗口、首次设置窗口都改成固定 760px 宽，不能拖动改变宽度。
- 底部状态区在所有状态下都排成一行，每一项都不折行、不截断。
- 官网上的 App 界面图和实际窗口一样宽。

## 非目标

- 不改窗口里的内容、文字和交互。底部状态区有新版本时的按钮是唯一例外。
- 不改弹窗、中转配置表单窗口、菜单栏或托盘菜单的宽度。
- 不改官网其他区块。
- 不做深色主题。

## 整体验证路径

1. 在 macOS 上打开主窗口：窗口宽 760px，拖不动窗口边框；状态区的「v0.1.0-local」和「检查更新」都在一行里。
2. 让本工具检测到新版本 0.2.0：状态区最右只有一个按钮「新版本 0.2.0」，点了打开下载页。
3. 在 Windows 上打开主窗口：宽 760px，拖不动；「最大化」变灰不能点；状态区一行。
4. 第一次打开本工具时弹出的首次设置窗口：两端都是 760px，宽度固定。
5. 打开官网，在浏览器窗口宽 1200px、700px、500px、320px 下分别看 App 界面图：分别是 760px、约 494px、约 319px、约 281px 宽，页面没有横向滚动条。

## 决策记录

- **宽度定为 760px，不是用户最初说的 720px**（用户 2026-11-19 在原型里选了方案 B）。原因：在原型里实测，720px 下有新版本时状态区放不下（最少要 732px）。被否决的两个方案：
  - 方案 A：保持 720px，按钮只写「有新版本」，版本号放进悬停提示。文字最长时只剩 16px 余量，而且看不到版本号。
  - 方案 C：加宽到 840px，文字照旧。余量只有 12px，以后文字再长还会挤，只是缓解症状。
- **有新版本时，把两段文字合成一个按钮「新版本 0.2.0」**。挤的根本原因是这一项多出约 121px，缩短它才是解决原因。被否决的是改用提示条提醒新版本，因为改动比这次大。
- **两端宽度都固定、不能拖动**（用户 2026-11-19 原话"和mac一样默认720切无法改变窗口宽度"，宽度后来按方案 B 定为 760）。Windows 原来允许拖窄到 450px，拖窄后状态区会被裁掉。
- **Windows 的「最大化」变灰不能点**（用户 2026-11-19 选定）。被否决的做法：去掉这个按钮，要改的地方更多；保持可用，最大化后会变宽，和"固定宽度"矛盾。
- **首次设置窗口一起加宽**（用户 2026-11-19 选定）。这样两个窗口宽度一致，DESIGN.md 里只需要写一个窗口宽度。
- **官网 App 界面图跟着加宽**（用户 2026-11-19 选定）。窄屏下的缩放比例重新算过，缩小后的界面图和原来差不多大，用户 2026-11-19 同意了这组比例。
- 已知风险：状态区宽度只在 macOS 字体下量过，Windows 字体本机量不了。做完后要在 Windows 真机上看一眼。
