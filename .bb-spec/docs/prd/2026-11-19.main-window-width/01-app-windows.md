# App 窗口加宽与状态区排版

## 用户故事

### P0：作为用户，我想让主窗口底部状态区整齐地排成一行，以便一眼看清版本和运行状态

**用例（主路径）**
- 场景：小林在 macOS 上装了版本 `0.1.0-local`，转发开着，中转有 17 个可见模型，配了 1 个中转配置。
- 操作：打开主窗口。
- 预期：
  - 窗口宽 760px。
  - 状态区从左到右排成一行：「v0.1.0-local」「● 后台运行中」「✓ ChatGPT 已检测到」「✓ 中转模型 17 个（1 个配置）」，最右是「检查更新」。
  - 版本号和「检查更新」都不折行。

**用例（边界 / 异常）**
- 场景：本工具检测到新版本 0.2.0。预期：
  - 状态区最右只有一个文字按钮「新版本 0.2.0」，点了打开下载页。
  - 不显示「发现新版本 0.2.0」和「打开下载页」这两段文字。
  - 状态区仍是一行。
- 场景：文字最长时，也就是后台服务已停止、ChatGPT 版本暂不支持、有新版本 0.11.0、本工具版本是 `0.10.0-local`。预期：状态区一行放下「v0.10.0-local」「后台服务已停止」「ChatGPT 版本暂不支持」「中转模型 转发关闭时不获取」「新版本 0.11.0」，没有一项折行或被截断。
- 场景：10 个中转配置，状态区写「128 个（10 个配置）」。预期：仍是一行。

### P0：作为 Windows 用户，我想让窗口宽度和 macOS 一样固定，以便状态区不会被裁掉

**用例（主路径）**
- 场景：小林在 Windows 上打开主窗口。
- 操作：拖动窗口左右边框，再点标题栏的「最大化」。
- 预期：
  - 窗口一直是 760px 宽，拖不动。
  - 「最大化」是灰的，点了没反应。
  - 高度仍然随内容变化。

### P1：作为第一次使用的用户，我想让首次设置窗口和主窗口一样宽，以便两个窗口切换时不会忽宽忽窄

**用例（主路径）**
- 场景：第一次打开本工具，弹出首次设置窗口。
- 预期：
  - macOS 和 Windows 都是 760px 宽，宽度固定。
  - 说明文字「填写中转服务提供的 Base URL 和 API Key。设置完成后，Codex 的模型列表里会多出中转模型。」排成一行。
  - 表单的标签列仍是 112px，输入框跟着卡片变宽。
  - Windows 上「最大化」是灰的。

## 约束

- C1 macOS 主窗口和首次设置窗口宽 760px；用户不能拖动改变宽度。
- C2 Windows 主窗口和首次设置窗口宽 760px；用户不能拖动改变宽度；标题栏的「最大化」不可用。两个窗口的高度都随内容变化。
- C3 底部状态区里的每一项（版本号、运行状态、ChatGPT 检测结果、中转模型数、最右的按钮）都只排一行，不折行、不截断。
- C4 有新版本时，状态区最右只有一个文字按钮「新版本 <版本号>」，点了打开下载页；它的可访问名称（读屏软件读出的名字）是「发现新版本 <版本号>，打开下载页」。没有新版本时，最右是「检查更新」，行为不变。
- C5 两端两个窗口里的其他内容、文字和交互都不变。

## 验收

- [ ] C1：在 macOS 上打开主窗口、首次设置窗口 → 宽都是 760px；拖窗口边框，宽度不变。
- [ ] C2：在 Windows 上打开两个窗口 → 宽 760px，拖不动；「最大化」是灰的，点了窗口不变。
- [ ] C3：在 macOS 上用「文字最长时」的数据（`0.10.0-local`、后台服务已停止、ChatGPT 版本暂不支持、转发关闭、有新版本 0.11.0）打开主窗口 → 状态区是一行，五项都没有折行或被截断。用 `0.1.0-local` 加「检查更新」的数据 → 版本号和「检查更新」都在一行里。
- [ ] C4：有新版本 0.2.0 → 状态区最右只有一个「新版本 0.2.0」按钮，界面上没有「发现新版本」「打开下载页」这两段文字；点按钮打开下载页；读屏软件读出「发现新版本 0.2.0，打开下载页」。没有新版本时显示「检查更新」。
- [ ] C5：两端两个窗口里其他文字和按钮都和改前一样（对照改前的界面逐项看）。

## 验证路径

1. 在 macOS 上运行本工具，打开主窗口 → 宽 760px，拖不动，状态区一行。
2. 让更新检查返回新版本 0.2.0 → 最右变成「新版本 0.2.0」，点了打开下载页。
3. 在 Windows 上重复第 1、2 步，再看「最大化」 → 是灰的。
4. 删除本工具的设置，重新打开 → 首次设置窗口宽 760px，宽度固定。
